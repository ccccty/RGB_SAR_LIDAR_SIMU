## 1. 它做什么

给一个 OBJ 模型、一个相机位置和一组天气，输出：

| 模态 | 成像方式 | 输出 |
|---|---|---|
| **RGB 可见光** | Blender 4.5 无头 Cycles 路径追踪 | 768×576 / 640×480 PNG |
| **红外 MWIR** 3–5 µm | 逐面能量平衡 → Planck 波段积分 → NETD 噪声 → NUC | 16-bit PNG + 8-bit 预览 |
| **红外 LWIR** 8–12 µm | 同上，独立发射率与大气窗口 | 16-bit PNG + 8-bit 预览 |
| **毫米波雷达** | 弓形布束 → 面元物理光学 (PO) → 雷达方程 → 二维匹配滤波 | **距离-多普勒图** + 距离-方位图 + 检出点 + 3D 框 |
| **SAR 条带式** | 侧视孔径 → 面元散射 → 距离-多普勒聚焦 → 相干斑 + NESZ | 8-bit 灰度图 + 分辨率/测绘带/SNR |
| **激光雷达 LiDAR** | 脉冲飞行时间 + 激光雷达链路方程 | 距离图 + 强度图 + PLY 点云 |
| **标注** | 三维包围盒投影（各模态共用） | COCO JSON、雷达点云 JSON、PLY |

关键点：**所有模态在同一帧里共享同一份三维世界与同一套天气状态**，
所以可以做跨模态配准、融合、以及"同一目标在不同传感器下长什么样"的对照研究。

**双视场**：一个片段可同时渲染窄视场（机载导引）与宽视场（搜索）两套图像，
同一时刻、同一世界、不同镜头，各自带独立标注与 COCO。

**训练格式**：`python tools\export_yolo.py` 直接导出 YOLO 数据集（按模态分套 +
多模态拼接图 + 跨模态配对表），细节见 [`docs/YOLO导出.md`](docs/YOLO导出.md)。

## 1.5 图形界面：点参数就出数据集

不想记命令行参数的话，双击 `run_studio.bat`（或 `python -m simkit studio`），
浏览器打开 <http://127.0.0.1:8808/> 就是一个本地工作台：

- 选场景 / 目标像素大小 / 距离趋势 / 天气 / 传感器 / 雷达频段 / 帧数 / 帧率 / 每段帧数
- **先预览 8 帧** 看对不对，再点 **生成数据集** 正式跑
- 实时进度条与日志、各模态样张、每个片段的轨迹事实（距离/像素/速度/加速度）

纯本地、零依赖、零 CDN，断网可用。详见 [docs/连贯数据集与工作台.md](docs/连贯数据集与工作台.md)。

**数据集是连续片段，不是独立帧堆**：一个片段内目标沿一条解析轨迹运动，
天气在片段内保持一致（或平滑演变），相邻帧只差一个积分步；拆块并行生成再拼接，
结果与单进程完全一致。

## 1.6 无人机导引视角与四种观测几何

`scenes/sk3_*.json` 是四个**无人机导引视角**场景。与早期"相机不动、目标飞过来"的做法相反，
这里**相机在动、目标基本静止**：飞行器沿一条解析的俯冲+蛇形轨迹接近目标，云台带一阶滞后
跟踪目标，画面里因此有真实的地速推移与横滚——这正是运动检测/跟踪算法要学的信号。

四种几何覆盖常见的接近观测谱系，`el_deg` 的符号决定相机在目标的上面还是下面：

| 场景 | 几何 | 高度关系 | 斜距 6 s 内 | 窄视场目标 | SAR |
|---|---|---|---|---|---|
| `sk3_high_air2air` | 高空空中目标 | 相机 +7.2°（在上方俯冲） | 7.7→6.2 km / 8.9→7.4 km | 2.9%–4.2% | — |
| `sk3_low_surface2air` | 上升接近 | 相机 −5°（地面起飞、爬升仰视） | 6.4→5.0 km / 7.4→6.1 km | 2.8%–4.2% | — |
| `sk3_low_air2air_occluded` | 低空空中目标 + 城市遮挡 | 相机 −1°（略低于目标掠飞） | 2.4→1.9 km / 3.0→2.4 km | 4.4%–7.0% | — |
| `sk3_low_air2ground_clutter` | 低空下视 + 地面杂物 | 相机 +2.6°（俯冲下视） | 2.7→1.7 km / 3.1→2.1 km | 2.6%–4.8% | ✓ |

要点：

- **目标只占很小一部分**。窄视场 2.2°/768 px，目标跨度 20–54 px；宽视场 18°/640 px，
  目标只有 2–5 px。数据集中"目标占画面比例"是逐帧记录在 `frames.json` 里的量，
  不是事后估计。
- **两段不是重复的六秒**。每个场景两段，方位按 ±22° 交替、斜距在场景区间内抽取，
  两段起始距离相差 300–1500 m（`plan.selftest` 有一条断言专门守这个）。
- **遮挡是算出来的，不是摆出来的**。城市遮挡场景的遮挡墙按每段真实的起飞位姿沿视线放置，
  每段前 ~30 帧目标被整块楼体挡住、之后重新捕获，实测遮挡 25%
  （`tools/make_seeker_scenes.py` 生成时会自己跑射线统计并打印这个数字）。
- **杂物是硬负样本**。下视场景里有同类的诱饵车（`label: false`）、路障、围栏、灌木与
  两个棚屋。诱饵车尺寸与目标同量级，靠"看到车就框"的检测器会在这里付代价。
- 空中目标不配 SAR：侧视条带 SAR 成像的是地面/海面散射面，对空中目标不成立。
  这是场景设计的取舍，不是缺功能。

## 2. 快速开始

**首次使用先建一次本地环境**（`env\` 不入库，克隆下来是空的；建好之后不用再管）：

```powershell
cd RGB_SAR_LIDAR_SIMU
python -m venv env
env\Scripts\pip install -r requirements.txt
set PYTHONPATH=%CD%
```

只有 numpy 与 Pillow 两个依赖，纯 CPU、不联网。光学模态另外需要一个免安装的 Blender；
其余四个模态是纯 numpy，没有 Blender 也能跑（命令里加 `--skip-optical`）。把整包拷到
离线机器的部署步骤与校验清单见 [`docs/离线部署.md`](docs/离线部署.md)。
站点探针与本地预览（`node tools\serve_web.js`、`node tools\probe_web.js`）另需 Node.js，
只在要本地起服务或跑站点自检时才用得上，生成数据本身不需要它。

环境就绪后，一条命令跑完整条流水线（三个场景 → 三份数据集 → 合并 COCO → 网站数据 → 缩略图）：

```powershell
set PYTHONPATH=%CD%
env\Scripts\python.exe -m simkit selftest     # 50 项自检，先确认内核没坏
env\Scripts\python.exe tools\build_all.py     # 全部跑一遍
node tools\serve_web.js                        # http://127.0.0.1:18080
```

`build_all.py` 只是按顺序调用下面四条命令并逐步计时、出错即停，等价于手打：

```powershell
# 1. 生成：6 帧、三天气、双波段红外 + 雷达 + 激光 + 光学
env\Scripts\python.exe -m simkit gen -c scenes\final_air_uav.json      -o out\final_air    -n 6 -s ir,radar,lidar,optical
env\Scripts\python.exe -m simkit gen -c scenes\final_ground_vehicle.json -o out\final_ground -n 6 -s ir,radar,lidar,optical
env\Scripts\python.exe -m simkit gen -c scenes\final_sea_boat.json     -o out\final_sea    -n 6 -s ir,radar,lidar,optical

# 2. 三个场景合并成一份 COCO
env\Scripts\python.exe tools\merge_dataset.py out\dataset out\final_air out\final_ground out\final_sea

# 3. 导出网站数据
env\Scripts\python.exe tools\export_web.py . out

# 4. 拼缩略图，肉眼过一遍
env\Scripts\python.exe tools\contact_sheet.py out\final_air out\sheet_air.png 6
```

只想刷网站不重跑仿真：`build_all.py --skip-gen`。
没有 Blender（或只是想快点）：加 `--skip-optical`，其余模态纯 numpy，秒级出图。

### 2.1 无人机导引视角数据集（四种观测几何）

```powershell
set PYTHONPATH=%CD%
env\Scripts\python.exe tools\make_seeker_scenes.py            # 生成 4 个场景配置（见下方注意）
env\Scripts\python.exe tools\build_seeker.py --jobs 3         # 4 场景 × 240 帧 × 5 模态 × 双视场
env\Scripts\python.exe tools\check_seeker.py out\seeker_air2ground   # 质量闸门
```

或者直接双击 `run_seeker.bat`（自动自检、找 Blender、按核数分块）。

> **注意**：入库的四个场景在 builder 输出之上另有手工补丁——`sk3_high_air2air` 与
> `sk3_low_surface2air` 带 `flight_class: "fighter"`（不加会被包线裁掉接近速度，
> 斜距永远收不拢），`sk3_low_air2ground_clutter` 带 `kinematics.min_altitude_m: 40`
> （这一趟的全部意义就是贴地冲场，类别默认的 60 m 会否掉它）。这些字段连同各自的
> `_why_*` 说明目前**只存在于 JSON 里，builder 不会再生成**，所以直接重跑上面第一条
> 命令会覆盖并丢掉它们。要重生成，先把这两处补丁回写进 `tools/make_seeker_scenes.py`
> （见 [`PLAN.md`](PLAN.md) 的 P1-1）。

- `--no-optical`：跳过 Blender，纯 numpy 模态，分钟级跑通全链路（调几何时用这个）
- `--jobs 3`：每个场景切 3 块并行；线程预算按 `核数/jobs` 自动分给每个 Blender，
  否则三个 Cycles 实例互相抢核，比单进程更慢（实测 64 s/帧 → 25 s/帧）
- `--skip-gen`：只重做合并、导出与缩略图

`check_seeker.py` 是闸门不是装饰，但**它的硬门禁只有两项**：`frames.json` 是否存在、
距离是否单调收拢。这两项任一不过就返回非零退出码，可以直接串进批处理。
另外三项——每个模态的出框率是否 ≥80%、SAR 目标对比度是否为负、两段片段长度是否一致——
只打 `[WARN]` 而不改退出码；它的 docstring 还宣称会检查"目标像素是否落在设计带内"，
但代码里并没有这个检查（只打印 `px_note`）。要逐项判定 `passed` 的完整闸门是
`tools/validation_check.py`，两者别混用。

网站也可以**直接双击 `index.html`**（`file://`）打开：
`tools/export_web.py` 除了写 `data/manifest.json`，还会写一份 `data/boot.js`
（同样的数据，包成一句 `window.SIMKIT_DATA = {...}`）。浏览器不允许
`file://` 下 `fetch`，但允许普通 `<script>`，所以断网机器上不用起服务也能看全部内容。

四个探针脚本可以直接复核（都不需要预先起服务，各自内嵌了一个临时静态服务器）：

```powershell
node tools\probe_web.js                      # 起临时服务，跑真实页面，查 11 个页签
node tools\probe_web.js https://...           # 换成查线上部署
node tools\probe_file.js                     # 查 file:// 双击打开
node tools\probe_canvas.js                   # 查画布真的画了东西、滑块真的会算
```

### 2.2 导出成 YOLO 训练集

训练集单独重渲染，落在 `out\ds4\`，不碰 `out\` 下已经发布到网站的那批运行：

```powershell
env\Scripts\python.exe tools\build_seeker.py --dest out\ds4 --no-web --jobs 6
env\Scripts\python.exe tools\export_yolo.py --runs out\ds4
env\Scripts\python.exe tools\yolo_sheet.py datasets/yolo optical   # 标注回放核对图
```

`--dest out\ds4` 是有意的：`tools\export_web.py` 会把 `out\` 下每个带 `meta.json` 的
目录当场景发布，240 帧的机载导引运行直接放进去会让网站数据从 127 帧跳到近千帧。
`--no-web` 再关掉合并 COCO、网站导出和缩略图，这条命令只做渲染。

`--fmt png` 出无损（体积约 4 倍）；`--scenes` / `--flavours` 可以只导一部分。

输出按模态分成多套数据集（`data_optical.yaml`、`data_ir_lwir.yaml`、`data_sar.yaml` …），
每套自带 `images/` 与 `labels/`，可直接 `yolo detect train data=...`。
`pairs.csv` 记录同一时刻各模态的图像路径，用于融合或多分支训练。

三条保证是写进生成流程的，不是导出时补救的：

- **连续性**：每场景 240 帧不抽帧（12 秒 / 20 fps，两段独立接近段各 6 秒）；
- **配准**：所有模态的框都由同一套三维投影算出，渲染器的掩膜只判可见性——
  导出时逐帧自检跨模态框偏差，实测 **0.00 px**。这是**标注**层面的一致性：
  各传感器成像机理不同（同一架无人机光学轮廓 30 px、红外机身 17 px），
  渲染出的图像本身并不逐像素相同，图像级配准目前只在航空链上有独立指标；
- **划分**：按片段切（clip 0 训练 / clip 1 验证），不随机切帧，
  避免相邻两帧同时进训练和验证。

细节与已知局限见 [`docs/YOLO导出.md`](docs/YOLO导出.md)。

## 3. 仓库结构

```
simkit/                仿真内核（纯 numpy）
  scene.py             JSON 配置 → 三角面世界；prepare_mesh() 是网格准备唯一入口
  mesh.py              OBJ 载入、顶点聚类抽稀、海面/平面生成
  bvh.py               向量化射线求交（雷达 / 激光 / SAR / 遮挡共用）
  thermal.py           逐面稳态能量平衡（太阳 + 天空 + 对流 + 内部热源）
  ir.py                Planck 波段积分、大气透过率、PSF、NETD、NUC/FPN
  radar.py             面元 PO 散射、雷达方程、MTI 门控、距离-多普勒合成
  sar.py               条带式 SAR：反射率图 + 距离-多普勒聚焦、相干斑、NESZ、分辨率自检
  lidar.py             脉冲 TOF、链路方程、PLY 导出
  weather.py           8 维天气状态机 → 三个模态的物理量
  motion.py            解析轨迹（直线/盘旋/8 字/蛇形/俯冲+蛇形）与云台（含滞后、横滚）
  plan.py              片段规划：轨迹 + 云台 + 双视场 + 天气时间线，按全局帧号可复现
  optical.py           Blender 调用封装（多视场、线程预算）
  dataset.py           帧循环、多视场标注、COCO、SAR/雷达逐帧索引
  selftest.py          内核自检（含 sar/plan 两个子模块的自检）
blender/render_optical.py   Blender 端渲染脚本（多视场、横滚、程序化地表、天空）
scenes/                 场景配置（高空空中目标 / 低空上升接近 / 城市遮挡 / 下视杂物 / 旧演示场景）
```

## 4. 物理模型要点

### 4.1 天气是一个状态机

8 个标量 `cloud_cover, visibility_m, rain_mmh, wind_ms, air_temp_c, rh, sun_elev_deg, sea_state`
经 `derive()` 变成每个模态各自消费的物理量。雨在光学、红外、雷达里是**同一场雨**。

- 能见度 → Koschmieder 消光 `β = 3.912 / V_km`
- 太阳 → `G_dir = 1361 · 0.75^(m^0.678) · sin(el)`，按云量做直射/散射分离
- 天空长波温度 → Swinbank 晴空值按云量向云底温度插值
- 雷达雨衰 → ITU-R P.838-3 `γ = k·R^α`，双程累计
- 激光消光 → 由 550 nm 的 Koschmieder 值按 `λ^-1.3` 折算，再叠加雨滴项

### 4.2 红外

逐面稳态热平衡：`α_solar·G + ε·σ·T_sky⁴·F_sky + h·(T_air − T) + q_int = ε·σ·T⁴`。
解出每面温度后做 Planck 波段积分，乘大气透过率，卷积高斯 PSF，加 NETD 噪声。

**NUC/FPN 在量化到 16-bit 之后施加**，种子取自配置而非帧号，所以固定图案噪声在整个数据集里是同一张，
符合真实焦平面阵列的行为。

### 4.3 雷达

弓形栅格逐条射线求交 → 每个面元按物理光学近似给 RCS：

`σ = 4πA²cos²θ/λ² · ρ² · coh`，`coh` 是 Kirchhoff 粗糙度衰减。

再走标准雷达方程 `P_r = P_t G² λ² σ / ((4π)³ R⁴ L)`，
噪声 `k·T₀·F·B·L`，处理增益是**二维阵列**的 `10log₁₀(n_samples·n_chirps)`
（`pn` 用的是 ADC 带宽噪声，后面的距离维 FFT 属于匹配滤波的一部分；
只算 chirp 维会凭空少 30 dB）。

六个频段预置：X / Ku / K / Ka / W / W94，各带自己的天线波束宽度与雨衰系数。

**距离-多普勒（RD）图**是雷达这一路的主产物：`n_samples` 个距离单元 × `n_chirps` 个
多普勒单元。它由**一个显示孔径**合成——所有回波按各自方向的双程天线方向图加权后
相参叠加、只加一个复高斯噪声场，所以噪声是单通道的指数散斑（10–90 分位差 13.4 dB），
与实测一致；每个目标由 K 个散射中心构成，在距离维占 2–4 个单元，动力机型再叠 ±k·f_blade
的叶轮梳齿（JEM）。

两个踩过的坑：跨波束**逐格取最大**曾是错的——1120 条波束取极大把散斑压成 3 dB 台地，
图上只剩一个白点（本次实测：噪声 10–90 分位差 1.83 dB）；单 PRF 下径向速度要折进
±λ/(4·pri) 再定位框，否则框会贴到 Nyquist 边缘。

成图与导出：`images/radar/` 是带距离/速度坐标轴、dB 色标与右上角目标参数表
（距离、径向速度、方位、SNR）的 RD 图；`images/radar_clean/` 是同一张图去掉参数表与
目标标记的**纯净版**（训练与论文并排展示用），`images/radar_ra/`、`images/radar_ra_clean/`
同理是距离-方位图的两版；
`raw/radar/NNNNNN.npy` 是 float32 功率张量 `(range, doppler)`；
`labels/radar/` 与 `annotations_radar.json` 给出逐帧真值（距离/闭速/方位/RCS/SNR）与图内框。

### 4.4 激光雷达

905 nm 脉冲，方位/俯仰栅格逐条求交。返回光子数按链路方程：

`N = E_t · (ρ/π) · (A_r/R²) · cos(inc) · exp(−2βR) · η / E_ph`

唯一一个仪器常数——"反射率 10% 目标的作用距离"——用来标定噪声底，
这样灵敏度是一个可核对的数字，而大气、反射率、距离仍然跟着物理走。

### 4.5 SAR（条带式）

侧视几何：平台沿航向匀速直线飞行，视向与航向垂直（正侧视），测绘带 `near..far` 由
`swath_center_m ± swath_width_m/2` 给出，`anchor` 是测绘带中心的地面坐标。

链路是「反射率图 → 二维聚焦」而不是逐脉冲射线（512 脉冲 × 1024 采样太慢）：

1. 在孔径中心时刻对 (方位 × 距离) 网格**一次性**射线求交，得到每个分辨单元的命中面元、
   入射角与材质复反射率（复用 PO 公式 `σ = 4πA²cos²θ/λ²·ρ²·coh`）；
2. 距离向按带宽 B 的 sinc² 加权（`ρ_r = c/(2B)`），方位向按合成孔径加权
   （`ρ_a ≈ 0.886·λR/(2L_sa)`，`L_sa = min(v·T_int, λR/L_ant)`）；
3. 每个分辨单元乘一个复高斯（幅度瑞利、相位均匀）得到相干斑，`looks` 控制多视平均；
4. 叠加按雷达方程算出的噪声底（NESZ），再按「噪声中位数为锚 + 固定动态范围 + gamma」拉伸到 8-bit。

两个反直觉点，都写进了自检：

- **天线越长，方位分辨率越差**（D/2 定律：`ρ_a = L_ant/2`）。加长天线让实波束变窄、
  可相干积累的合成孔径变短。想提高方位分辨率应该**增加相干积累时间**（`n_pulses`↑、`prf`↑
  或平台速度↓），而不是加长天线。实测：L=1 m → 0.86 m，L=4 m → 1.77 m。
- **距离分辨率与斜距无关**，只由带宽决定；但地面投影分辨率是 `ρ_r/sinθ_inc`，
  掠射角下会退化，配置里可以直接看到 `incidence_deg`。

`simkit/sar.py` 的 9 项自检里，每一项都是可对账的物理量：距离分辨率 −3 dB 实测 1.014 m
（理论 0.999 m，+1.5%）、点目标峰值位置误差 0–1 px、发射功率 +3 dB → SNR +3.01 dB、
测绘带内地面回波比带外高 53 dB、目标 bbox 与真实几何偏差 0 px。

SAR 逐帧按「快照」生成：每帧的 `anchor` 跟随目标，沿航迹时间置零。原因是 6 秒 × 180 m/s
约 1 km 的位移会把目标推出几百米宽的方位窗——这不是精度问题，是成像几何问题。
`tools/sar_check.py` 与 `simkit/sar.py selftest()` 都能复现这两个数字。

## 7. 验证过什么

- `python -m simkit selftest`：内核 + SAR + 轨迹规划共 **50 项全 PASS**
  （含 `sar.selftest()` 9 项、`plan.selftest()` 8 项）
- **SAR**：距离分辨率 −3 dB 实测 1.014 m vs 理论 `c/2B` 0.999 m（+1.5%）；点目标峰值位置
  误差 0–1 px；发射功率 +3 dB → SNR +3.01 dB；测绘带内地面回波比带外高 53 dB；
  单帧 3–14 s、峰值内存 665 MB。方位分辨率按 D/2 定律随天线变长而变粗（L=1 m→0.86 m，
  L=4 m→1.77 m），随相干积累时间变长而变细（n_pulses 256→1024，1.73 m→0.43 m）

  严格成反比（误差 0.00%）；分块生成与整段生成逐帧一致（含片段中间帧）；横滚在限幅内
- **遮挡**：`tools/make_seeker_scenes.py` 生成场景时自己跑射线统计，城市场景每段前 30 帧
  被楼体挡住（25%），其余帧正常；标注侧的出框率与之严格一致（75%）
- **站点**：`node tools/probe_web.js` 在真实数据上 11 个页签全开、0 JS 错误、
  0 张破图、每个模态都真的载出图（`badMods: []`）
- **跨模态配准**：同一时刻、共用位姿的各模态，框由同一套三维投影导出，
  导出时逐帧自检 **240 对框最大偏差 0.00 px**。这条是构造出来的，不是事后对齐：
  渲染器的 id 掩膜只判可见性，不参与定框位置（否则光学轮廓框 30 px 与红外机身框 17 px
  会让同一目标差 4 px）
- **雷达 RD**：三场景 60 帧全部出点目标框，检出率 20/20（高空空中目标）、19/20（上升接近）、
  15/20（下视接近，余下几帧是 0.5 m² @2.6 km 的链路预算真不够，不是漏标）；
  框所在行的最亮格就是框心格，行内峰值 37–235 vs 全图均值 4.6
- **YOLO 导出**：图/标签一一对应、孤立文件 0，train/val 按片段切所以跨 split 无重复文件
  （这两条是构造保证的，见 `tools/export_yolo.py` 的按 clip 切分）；标签行数、拼接图坐标
  重建误差与跨模态框对数是**批次性的**，随当次导出的 run 变化，以 `export_yolo.py`
  打印的当次摘要为准，不在这里写死数字
- 光学亮度对齐 11 张实拍无人机照片（天空 luma 135/150/161/191/226，目标比天空暗 39–52 级）
- 红外 NUC 固定图案相关 0.962；LWIR 目标对比度 +59…+81 灰阶

## 8. 已知局限

1. **雷达 RCS 是几何 PO 估计 + `rcs_db` 覆盖值**，不是实测。无人机 +1.5 dBsm 是合理占位值。
   换一个 RCS 假设，作用距离会显著移动（表在 §7），但整套流程不用改。
2. **SAR 是「快照」而不是整段条带**。逐帧把 `anchor` 锚到目标、沿航迹时间置零，
   所以每帧都是一次独立的正侧视快照；6 秒 × 180 m/s ≈ 1 km 的位移若照实积累，
   目标会滑出几百米宽的方位窗（这是成像几何，不是精度）。真正的连续条带需要
   把一圈合成孔径分摊到多帧，属路线图。
   代价是**序列准静态**：20 帧里目标只漂 2–3 px，帧间差异主要是斑点噪声，
   作为检测样本信息量有限（改进方案见 [`PLAN.md`](PLAN.md) 的 P0-3）。
3. **SAR 的散射是面元 PO + 相干斑，没有多次散射、没有阴影遮挡、没有极化统计**。
   `polarization` 只影响反射率取值，不产生 HH/VV 的统计差异。
4. **城市遮挡场景的遮挡是整块楼面填满视场**，不是"目标被楼角切掉一半"。
   窄视场 2.2° 在 260 m 处只有约 10 m 宽，任何能挡住目标的实体都会填满画面——
   物理上如此，视觉上就是「短时丢失再重捕获」。
5. **目标外形是真实模型，尺寸是设计值**。素材模型原生翼展 417 m，按
   `target_m` 缩放到 8–11 m 量级；也就是说轮廓来自真实几何，绝对尺寸由场景指定。
6. **海面是六正弦叠加**，无白冠、无破碎波；海气温差未建模。
7. **MWIR / LWIR 预览图高度相关**（相关系数 0.995+），因为同一表面温度主导两者；
   波段差异在 16-bit 原始计数里（平均 46–63 counts ≈ 175–240 mK）。
8. **天气只有晴/阴/雨三档**，缺雾、雪、沙尘。
9. 光学只标定了天空亮度，地面与阴影未单独标定；程序化地表纹理是观感手段，
   不是辐射标定。
10. 单帧耗时（CPU，无人机导引视角场景 5 模态 × 双视场）：雷达 ≈19 s、红外 ≈12 s、SAR ≈5 s、
    光学 ≈13 s、激光 ≈2 s。雷达现在是最慢的一环（1024 采样 × 256 chirp 的二维匹配滤波）；
    分块并行时务必给每个 Blender 分配线程预算，否则互相抢核反而更慢。
11. **场景里存在与目标同型、但故意不标注的诱饵车**（`decoy_rover`），
    在雷达/SAR 上的回波甚至比目标更强。作为"搜索阶段的硬负样本"是合理的，
    但导出成检测数据集后属于"同类不标"，会扣检测器的分——处理方案见
    [`PLAN.md`](PLAN.md) 的 P0-1。

本项目是**仿真工具**，输出用于算法训练与验证；数值为工程近似，不替代实测标定。
