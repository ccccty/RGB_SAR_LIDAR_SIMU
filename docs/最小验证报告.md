解析检测 SNR 与复数据读数不是同一口径：前者是雷达方程的期望信噪比（标注里 detection_basis = expected radar equation SNR，另含处理增益），属于设计预算；后者是本帧功率立方体里峰值与噪底中位数之比，属于随帧变化的实测动态范围。验收采用后者，因为它可以被任何拿到 raw/radar/*.npz 的人独立复算。

干扰窗为 0.20 s 到 0.90 s，窗两端各带 0.1 s 淡入淡出（smoothstep）。权重为 0 的帧必须与干净数据逐码一致，权重为正的帧必须被改写——这一对照同时证明“干扰确实落到栅格上”和“没被干扰的帧没被动过”。

- 期望权重为 0 且实测差为 0 的帧：0、1、2、9。
- 期望权重为正且实测差大于 0 的帧：3、4、5、6、7、8。

窗起点 t = 0.20 s 正好落在淡入的 u = 0 处，权重恰为 0，所以帧 2 虽然名义上“在窗内”，交付栅格必须与干净数据完全一致；这是淡入的设计结果，不是漏施加。

注意：干扰只重建图像栅格与标注，不重建回波点云与原始复数据；radar/lidar 的 3D 真值仍是干净参考值。

## 九、负向对照（判据确实会失败）

一个从没失败过的判据不是判据。tools/validation_negative.py 把本次产物复制一份，注入四种互不相关的缺陷后交给同一个 tools/validation_check.py；注入之外的内容逐字节未改，所以多出来的任何一条错误都会是误报。

| 注入的缺陷 | 对应判据 | 脚本报出的错误 |
|---|---|---|
| optical 第 3、7 帧的目标框被涂成背景天空 | 看得见 | optical: target peak deviation from its background ring below 20 codes on frames [3, 7] |
| lidar 第 5 帧的目标框被挪到空白角落 | 标得对 | trajectory: lidar target jumps 146.7 px per frame |
| ir 第 2 帧的文件被截断 | 读得出 | ir_mwir frame 2: image does not decode (Truncated File Read) |
| radar 第 9 帧的标注被删除 | 对得齐 | radar: missing label 000009.json |

被注入缺陷的副本判定为**不通过**（passed = False），四种缺陷全部检出：是。

四条缺陷分别落在“看得见”“标得对”“读得出”“对得齐”四个独立维度上，每条都被定位到具体帧号，脚本退出码为 1；干净产物在同一脚本下退出码为 0。两个方向都跑过，才说明这道门禁既不放过坏数据，也不误杀好数据。

## 十一、已知局限

1. 雷达 RCS 是几何面元的物理光学叠加再被 rcs_db 覆盖；8 dBsm 是让检测门限落在有意义位置的设定值，不是该型飞机的实测值。
2. SAR 是地面平面成像近似。参考面被放到目标高度、天线沿自身直线航迹飞行，因此它与光学不同轴，只能保证同一帧号对应同一时刻与同一目标，不构成像素级配准。
3. 红外只有中波单波段，16 bit 计数未经实测辐射定标；本报告只用相对对比度。
4. 运动是解析航路加协调转弯运动学，没有六自由度气动积分；包线检查是采样检查，不是对任意连续曲线的数学保证。
5. 本报告第七节测的是**图像域干扰增广**（interference.py）：它在交付栅格上叠加，改变的是像素码值，不改变物理量。这是刻意保留的一条独立分支，与物理层并列而非替代。
   物理层的场景级干扰另在 `simkit/ecm.py`，覆盖有源（压制 / 转发假目标 / 距离-速度门拖引 / 角度欺骗）与无源（箔条 / 角反射器 / 拖曳诱饵 / 红外诱饵）九类实体，每个实体有自己的位置、速度、尺度与寿命，真实进入雷达回波表与光学三角形，演示场景 `scenes/ecm_demo_fighter.json` 与报告 `docs/干扰增广与整体架构.md`。
   本报告的数据集（`out/validation_ecm`）在该模型加入之前生成，因此其中的干扰镜像仍来自图像域分支；两者不可混为一谈。
6. 本报告只证明管线、几何、标注与可见性，不证明训练效果，样本量 10 帧也不足以训练。
7. 场景里用的是显式模型路径 assets/models/军用飞机/双发战斗机.obj，不是资产卡写法：scene.load_config 目前不调用 simkit.asset.expand_scene，写资产卡的场景会静默退化成方块目标。在场景层修好之前，任何需要用真模型的场景都必须写显式路径。

## 十二、复现

```
set PYTHONPATH=%CD%        # 在仓库根目录下执行
env\Scripts\python.exe -m simkit validate -c scenes\validation_twin_fighter.json -o out\validation_ecm -n 10 -s optical,ir,radar,lidar,sar
env\Scripts\python.exe -m tools.validation_check out\validation_ecm --report docs\最小验证报告.md
env\Scripts\python.exe -m tools.validation_negative out\validation_ecm
```

- simkit validate 写 out/validation_ecm/validation.json（预检 + 产物检查）。
- validation_check 写 out/validation_ecm/quality_validation.json 与本报告，退出码 0 表示全部判据通过，1 表示有未通过项。
- validation_negative 写 out/validation_ecm/negative_control.json，退出码 0 表示四种注入缺陷全部被检出。

第二次运行 validate 前必须先换一个新的输出目录，cmd_validate 会拒绝写进已有数据集的目录，这是刻意的保护：验收报告不能被一次误跑覆盖成“通过”。
