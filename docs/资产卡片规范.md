# 资产卡片规范

把「一堆 OBJ 文件」和「有物理意义的仿真目标」之间的缺口补上。

## 1. 为什么需要它

改造前，同一个模型在多个场景里被重复手填参数：

    ds_air_uav.json      uav_global_haw  global_hawk.obj  scale=0.0956  rcs_db=1.5  temp_c=34
    hero_air_uav.json    uav_global_haw  global_hawk.obj  scale=0.0956  rcs_db=1.5  temp_c=34

参数跟着场景走，不跟着模型走。换个场景就要重抄一遍，抄错没有任何提示。

资产卡片让参数跟着模型走，场景只写一行引用。

## 2. 三层数据

| 层 | 内容 | 谁维护 | 可否手改 |
|---|---|---|---|
| 几何事实 | 包围盒、面数、分组、材质名、旋转角 | `tools/asset_scan.py` 自动扫描 | 不可，重扫即覆盖 |
| 型号档案 | 真实尺寸、RCS、热特征、材质、飞行包线 | `assets/profiles/_type_profiles.json` | 是，须带来源 |
| 反查表 | 泛称 → 型号列表 | `tools/asset_profiles.py` 自动生成 | 不可 |

分开维护的理由：重扫不能覆盖人工整理的数据，人工整理也不能伪造几何事实。

## 3. 场景怎么写

    {
      "objects": [
        {
          "asset": "军用飞机/单发战斗机",
          "profile": "F-16C Fighting Falcon",
          "pos": [0, 0, 120],
          "vel": [4, -2, 0],
          "rot": 200
        }
      ]
    }

`asset` 是「类别/模型名」，`profile` 是型号名（可省略，默认取第一个）。
展开器会补齐 `model`、`shape`、`scale`、`mat`、`temp_c`、`thermal_regions`、`material_map`。

场景里显式写的字段优先，所以仍可以针对单个场景覆盖某个参数：

    {"asset": "军用飞机/单发战斗机", "scale": 2.0}

## 4. 尺度怎么定

没有一个轴可以单独作准。两个扭曲叠加：

1. 模型被随手旋转摆放。实测 52 个模型里 27 个是斜的（战斗机 37–48 度），
   轴对齐包围盒因此虚大 22–30%。
2. 代理模型的轮廓和真实机型对不上。战斗机模型长宽比 0.90，真实 F-16 是 1.51。

所以按三个尺寸做对数最小二乘拟合，取使整体误差最小的尺度，
并把残差 `scale_log_rms` 记进卡片。残差大的模型会被标出来 —— 它说明这个
代理不可能被缩放成一个形状正确的 F-16，只能当尺寸近似用。

## 5. RCS 只作校验，不作输入

档案里的 `rcs` 不会 被写进 `rcs_db`。

因为 `rcs_db` 是标量覆盖，一旦填了它，雷达就不再做面元计算，RCS 随姿态角
几十 dB 的起伏也随之消失。而那个起伏正是检测任务最有价值的信息 —— 一个恒定
RCS 的目标会把检测退化成查表。

档案里的 RCS 交给 `tools/asset_check.py` 做量级校验用。

## 6. 证据分级

每个数值必须带分级，没有分级的数值不允许写进档案：

| 分级 | 含义 |
|---|---|
| measured | 暗室或外场实测 |
| literature | 本机型公开值 |
| estimated | 由同族缩放、分波段外推，或第三方推演数据库 |

采集中确认的两个重要事实：

- MQ-9、RQ-4、翼龙-2、彩虹-5、TB-2 均无公开实测 RCS。标注为 estimated 的值
  来自第三方推演数据库，不可当实测引用。
- 碳纤维/凯夫拉蒙皮是介电体，强散射体是内部金属件。把复合材料无人机按理想
  导体建模会系统性高估 RCS。

## 7. 工具

    # 扫描全部 OBJ，重建几何事实
    python tools/asset_scan.py

    # 合并型号档案，生成反查表
    python tools/asset_profiles.py

    # 单目标 RCS 量级校验
    python tools/asset_check.py "军用飞机/单发战斗机" --profile "F-16C Fighting Falcon"

    # 全部档案批量校验
    python tools/asset_audit.py --band-ghz 15

## 8. 已知问题

面元 RCS 不是网格无关的。同一块 1 平方米平板，单面元给出 19.6 平方米，
分成 256 个面元后只剩 0.10 平方米，差 192 倍。原因是逐面元按 A²/λ² 相加，
面元越碎总贡献越小。这意味着「模型精细度」实际上是一个隐藏的雷达参数。

现有扫描结果里，大目标偏高 14–34 dB，小目标偏低 9–23 dB，正是这个缺陷的表现。
修复需要改为相干求和（先求场再求功率），属于仿真器内核改动，未包含在本次交付中。
