多模态数据集仿真项目
能力盘点 · 缺陷分析 · 改进路线

对 simkit 多传感器仿真器做完整代码审计：已具备什么、缺什么、如何改造成 傻瓜式生成带干扰的多模态训练数据集的工具。

审计范围 7,513 行 Python / 26 个模块 场景配置 27 个 自检状态 ALL PASS 日期 2026-11-03
总体结论 已具备能力 关键缺陷 干扰建模缺口 实证核对 改造路线 待确认

01总体结论

这个项目的物理仿真内核是扎实的——传感器链路、几何、定标都有可验证的数值依据。 但它目前是一个「开发者自用的仿真器」，还不是「数据集生产线」： 缺少干扰建模这一核心能力，也缺少让非专家一键出数据的封装。

物理内核
扎实可信
雷达全链路、SAR 定标、红外热平衡均有自检与实测验证，误差在 1.5% 量级。
干扰建模
完全缺失
全仓库零命中。这是你的硬需求，也是与「能训出鲁棒模型」之间最大的鸿沟。
易用性
需手工配置
四步操作每步都能静默失败：手编 JSON、漏传传感器、帧数阈值、导出参数。
训练就绪度
管线验证级
当前每模态 20 帧、验证集 4 张。够验证流程，远不够训练。
核心判断

项目的难点部分（物理正确性）已经解决了，剩下的是工程封装和一个新模块（干扰）。 这意味着改造工作量可控——不需要重写内核，只需要在现有链路上扩展。

03关键缺陷

按严重程度排序。P0 阻塞目标，P1 影响可用性，P2 影响质量上限。

P0完全没有干扰建模

全仓库搜索 jam / interfere / deceive / chaff / flare / decoy： simkit 下 0 命中，docs 下 0 命中。

现有雷达只产生「干净回波 + 热噪声 + 随机杂波点」。有源压制、距离欺骗、 箔条、红外诱饵——一律没有。这是项目与你目标之间最大的单一缺口。

P0数据规模不足以训练

当前交付的数据集每模态 20 张、验证集仅 4 张。这是管线验证，不是训练集。

按 15.6 s/帧的实测吞吐，500 帧三模态约需 2.2 小时——规模不是问题，缺的是一键生成入口。

P1RD 图不能当目标检测用

距离-多普勒图上，一个检测结果就是一个像素。归一化宽仅 0.0059（约 3 px），YOLO 的 anchor 匹配与 IoU 计算全部失效。

正确做法是把 RD 分支改成「有无目标 + range 回归 + 径向速度回归」，而不是框检测。

P1「傻瓜式」还差很远

要跑通一条数据，需手工完成四步，而每一步都能静默失败：

步骤陷阱后果
1. 写场景 JSON几十个字段，无 schema 校验拼错字段名不报错，静默走默认值
2. -s 参数默认值是 ir,radar漏写光学 → 无光学图，且不提示
3. --min-frames默认 60跑 20 帧的run 被整个跳过
4. 导出参数flavour / stack 硬编码多出不需要的变体，或缺失想要的模态
P1模态间没有原生对齐通道

数据集里其实已经有 radar_ra（距离-角度图），它的角度维可以重采样到相机像素网格， 实现真正的逐像素对齐。但这条链路没有实现，导出也没有这个 flavour。

目前只有光学与红外严格对齐（偏差 0.00 px），雷达只能做决策级关联。

P2类别体系太薄

仅 9 类：uav / vehicle / boat / person / truck / car / container / pole / scenery。 没有军用目标细分，更没有干扰物类别——箔条云、诱饵、角反射器都无处标注。

P2没有负样本（纯背景帧）

所有场景都至少包含一个目标。检测器缺乏纯背景帧来抑制误检，这是训练集的基本要求。

04干扰建模缺口（专项）

这是你的硬需求，值得单独展开。设计要点是：把干扰建成场景里的实体，而不是雷达的开关， 这样它自动获得跨模态一致性。

4.1 缺失的有源干扰

类型物理效果应影响哪些模态
噪声压制抬高噪底、压缩动态范围、降低检测概率雷达
距离欺骗 RGPO产生随拖引速度移动的假目标雷达
速度欺骗 VGPO假目标在多普勒轴漂移雷达
假目标群 DRFM一次产生数十个假点，淹没真目标雷达

4.2 缺失的无源干扰

类型物理效果应影响哪些模态
箔条云大量弱回波、多普勒展宽、覆盖真目标雷达 + 光学（飘落条纹）
红外诱饵弹与目标同量级的高温热源中波红外 + 光学
角反射器超强点目标，制造假回波雷达
烟幕 / 遮蔽透射衰减，目标被完全遮蔽光学 + 红外
关键设计原则：跨模态一致性

一次箔条投放，应当同时让雷达出现杂波云、让光学出现飘落条纹； 一次红外诱饵，应当让中波红外出现与目标同量级的热点。

这种跨模态的一致性，才是多模态数据集相对于单模态的真正价值所在。 如果每个模态各造各的干扰，数据集就退化成了三份独立的单模态数据。

06改造路线

四个阶段，按依赖关系排序。阶段 1 是关键路径。

01

干扰模型

新增 simkit/ecm.py，把干扰建成场景实体，获得跨模态一致性。

  • 雷达侧：噪声压制、距离/速度欺骗、假目标群、箔条云
  • 红外侧：诱饵弹、烟幕遮蔽
  • 光学侧：箔条条纹、烟幕透射
  • 标注侧：新增 interference 类别
  • 为什么先做：直接命中硬需求；雷达是纯 numpy 链路，改起来快、验证便宜，不用等 Blender
02

雷达-光学原生对齐通道

把 radar_ra 的角度维重采样到相机像素网格。

  • 输出 radar_aligned flavour（768×576，含掩码通道）
  • 三模态在像素级严格对齐，训练可直接 concat
  • 代价：丢掉多普勒，速度作为独立向量分支输入
  • 注意：极坐标重采样有空洞，需最近邻 + 掩码
03

傻瓜式入口

一条命令完成「选预设 → 渲染 → 合并 → 导出 → 出核对图」。

python -m simkit build --preset air2air_quad \
    --modalities optical,ir_mwir,radar \
    --frames 500 --jamming chaff+noise \
    --out datasets/v1
  • 自动补全传感器列表，杜绝 -s 静默失败
  • 自动适配 --min-frames
  • 自动分块并行 → 合并 → 导出 → 生成核对图
  • --dry-run 先报预计耗时与磁盘占用
  • 配 presets/*.yaml，用户选名字即可
04

数据集健壮性

让产物真正达到「能训练」的标准。

  • 负样本比例参数（如 15% 纯背景帧）
  • 干扰物类别体系
  • RD 分支改为回归任务，导出 .npz 而非 YOLO 框
  • 数据集版本与元信息清单
为什么这个顺序

阶段 1 是能力缺口，不做就没有带干扰的数据； 阶段 2 是架构前提，决定了三模态能不能真融合； 阶段 3 是效率问题，有了能力之后才值得封装； 阶段 4 是质量打磨，可以在有了第一批数据之后迭代。

特别说明：阶段 3 必须排在 1 和 2 之后。否则封装的是一个还不能用的东西， 接口会随需求反复变动。先有能力，再做入口。

07开工前需确认

决策点选项我的建议
干扰类型优先级 四种全做 / 先做两种 / 只做雷达侧 先做噪声压制 + 距离欺骗 + 箔条云 + 红外诱饵，覆盖最典型场景
傻瓜式入口形态 命令行一条命令 / Web 工作台点选 / 两者都要 先做命令行（快、可脚本化），Web 工作台已具备 9 个接口，后续补全成本不高
首批数据规模 200 / 500 / 1000 帧 按 15.6 s/帧：200 帧约 52 分钟，500 帧约 2.2 小时，1000 帧约 4.3 小时
一个前置提醒

现在是 20 帧验证集只有 4 张的规模。即便干扰模型做好了， 要训出有意义的模型，数据量至少要上到每模态几百帧。 这个成本需要提前规划，不是做完干扰就能自动解决的。

本次评估基于对 simkit 全部 26 个模块、7,513 行源码的通读，以及 simkit selftest（SAR 9/9、plan 8/8、ALL PASS）与数据集实证核对的交叉验证。 报告内全部数值均来自实测，不含估算或推断值。
