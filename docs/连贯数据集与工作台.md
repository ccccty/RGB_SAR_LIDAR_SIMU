# 连贯数据集与本地工作台

这一版改的是三件事：**数据集从「图片堆」变成「连续片段序列」**、**红外/雷达的辐射与检测模型按公开经验公式重做**、**加了一个点参数就出数据集的本地工作台**。

---

## 1. 之前的数据集为什么不连贯

旧版 `plan_frames` 每帧独立抽样，四个地方都在破坏时序：

| 位置 | 旧做法 | 后果 |
|---|---|---|
| `randomize.placement` | **每一帧**重新随机目标位置 | 目标逐帧瞬移，相邻帧无因果关系 |
| `weather.states_of` + `wstates[f % len]` | 逐帧轮换天气预设 | 晴→云→雨→晴，天气逐帧闪烁 |
| `sensor_jitter_m` / `pose_jitter_*` | 逐帧独立高斯噪声 | 相机和目标都在抖，不是运动 |
| `temp_jitter_c` / `sun_az_jitter_deg` | 逐帧独立 | 光照与温度逐帧跳变 |

实测后果很直接：修复前生成 16 帧，目标框中心**每一帧都是 (240.0, 173.0)**——因为相机每帧都重新对准随机位置。这种数据训练出来的检测器只会学到「目标在图中心」。

## 2. 片段模型

一次运行由若干**片段（clip）**组成。一个片段拥有同一条轨迹、同一套相机机架、同一条天气时间线，所有量都是片段时间的解析函数：

```
pos(t)、vel(t)   解析给出，速度是位置的导数，不是另抽样
camera(t)       机架带因果滞后，不是逐帧噪声
weather(t)      片段内一种天气，或平滑过渡
```

片段号与局部时间由**全局帧号**推出：

```python
clip = f // frames_per_clip
t_local = (f - clip * frames_per_clip) * dt
```

所以把 500 帧拆成 4 个进程并行生成再拼接，结果和单进程逐帧跑**完全一致**——这正是 `--part k/N` 能安全并行的原因。

## 3. 轨迹族（`simkit/motion.py`）

| mode | 形状 | 速度 | 典型用途 |
|---|---|---|---|
| `line` | 匀速直线 | 常量 | 平飞接近 |
| `arc` | 协调转弯（恒速恒角速率） | v·ω 向心加速度 | 盘旋 |
| `figure8` | Lissajous 8 字 | 连续变化 | 机动目标 |
| `weave` | 直线 + 正弦横摆 | 有界横向加速度 | 规避机动 |
| `waypoints` | 向心 Catmull-Rom 样条 | 恒定线速度 | 手工航路 |
| `static` | 静止 + 微小摆动 | ≈0 | 停车/悬停 |

向心参数化是必要的：均匀 Catmull-Rom 在间距不均时会自交并产生尖点，表现为目标原地卡顿。

实测（12 秒、dt=0.2 s）：

```
mode       step max   speed med   |v-analytic - v-fd|
line        4.123 m    20.62 m/s    1.9e-11
arc         5.001 m    25.00 m/s    1.8e-07
figure8     5.651 m    18.37 m/s    8.6e-07
weave       4.681 m    21.09 m/s    8.9e-06
waypoints   3.000 m    15.00 m/s    0
static      0.049 m     0.18 m/s    8.2e-07
```

横摆的加速度是可查的：`figure8` 1.1 g、`weave` 2.9 g，都在真实机动包线内。

## 4. 导引头几何：目标要「差不多能看见」

导引头视角下目标不能占满画面。所以目标不再用世界坐标描述，而是用**传感器极坐标** `R(t), az(t), el(t)`，并且**距离由像素尺寸反解**：

```
px = L · W / (2 · R · tan(FOV/2))
R  = L · W / (2 · px · tan(FOV/2))
```

（L 为目标的视在尺寸，W 为图像宽，FOV 为视场角）

配置里写 `target_px: [10, 55]` 就保证目标落在这个像素区间，`target_m` 指定用来推算的视在尺寸（无人机 40 m 翼展正对时只有几米，用包围盒会高估）。

| 场景 | 视场 | 距离 | 目标像素 | 闭合速度 |
|---|---|---|---|---|
| 空中无人机 | 2.2° | 4.3–6.7 km | 18–29 px | 150 m/s |
| 地面车辆 | 6.0° | 270–590 m | 24–52 px | 8 m/s |
| 海面船只 | 3.0° | 2.8–7.3 km | 13–35 px | 12 m/s |

两个细节决定了它像不像导引头：

**LOS 游走（`wander_deg`）**：完美跟踪会把目标钉死在光轴上，检测器只会学到「目标在中心」。真实的机架有跟踪误差，所以瞄准点按几十分之一视场的平滑正弦漂移，目标才在画面里扫过。

**机架滞后（`lag_s`）**：相机对准的是 `target(t - lag)`。用纯时延而不是递推滤波器，是因为它因果、解析、且与分块边界无关——一个片段拆成两半仍然是一条连续的摇摄。

## 5. 天气：既要「不同天气的数据集」，也要片段内自洽

| mode | 含义 | 生成什么 |
|---|---|---|
| `fixed` | 整份数据集一种天气 | 专项数据集（全雨天集） |
| `per_clip` | 每个片段抽一种预设 | 一份数据集多天气，片段内一致 |
| `evolve` | 片段内从一种预设平滑过渡到另一种 | 天气渐变，smoothstep 插值的 8 个物理量 |
| `cycle` | 旧行为（逐帧轮换） | 仅为兼容旧配置保留 |

推荐 `per_clip`：同一份数据里有晴/云/雨/雾，但每个片段内部天气不跳变，模型学到的是「这种天气下目标长什么样」，而不是「第 3 帧一定下雨」。

## 6. 本地工作台（`simkit/studio.py`）

```
env\Scripts\python.exe -m simkit studio -p 8808
```

然后打开 http://127.0.0.1:8808/ 。纯本地、零依赖、零 CDN，断网可用。

界面四块：

1. **选参数**：场景 / 目标像素大小 / 距离趋势 / 天气 / 传感器 / 雷达频段 / 帧数 / 帧率 / 每段帧数 / 种子 / 输出名
2. **看结果**：任务进度条 + 实时日志 + 各模态样张
3. **轨迹与连续性**：每个片段的起止距离、起止像素、速度、加速度
4. **已生成的数据集**：列表 + 一键查看样张

两个按钮：**先预览 8 帧**（约 40 秒，先看对不对）、**生成数据集**（正式跑）。

HTTP 接口（可直接脚本调用）：

```
GET  /api/presets            场景与选项
GET  /api/plan?preset=&frames=   每片段轨迹事实
POST /api/generate           开始生成
POST /api/preview            预览 8 帧
GET  /api/jobs               任务列表
GET  /api/job/<id>           单任务状态与日志
POST /api/job/<id>/cancel    停止
GET  /api/img/<id>/<path>    取图
GET  /api/datasets           已有数据集
```

## 7. 物理修正

两份联网调研的完整推导与出处见：

- [IR_经验模型与改进方案.md](IR_经验模型与改进方案.md)（36 KB，680 行）
- [雷达与激光雷达仿真经验公式手册.md](雷达与激光雷达仿真经验公式手册.md)（35 KB，770 行）

### 7.1 红外（改动最大）

| # | 问题 | 修正 | 量级 |
|---|---|---|---|
| A1 | **没有路径辐射项** | `L = τ·(ε·B(Ts)+(1-ε)·L_env) + (1-τ)·B(T_air)` | LWIR 3 km 时占信号 39%，等效 23 K；缺失会让「远=冷」成为假相关 |
| A2 | 宽带天空温度直接代入波段普朗克 | 波段耦合系数 `κ_band`（MWIR 0.04–0.12，LWIR 0.40–0.55） | MWIR 天空原来高估约 5 倍，天空和地面几乎同亮度 |
| A3 | 常数消光 0.10/0.06 km⁻¹ | Kruse/Kim 气溶胶 + 水汽吸收 `β=k0+k1·w` | 真实夏季 0.35–0.45 / 0.15–0.25，10 km 处透过率高估 2–4 倍 |
| A4 | Swinbank ×(1−0.25RH) | Clark-Allen 天空发射率 + Walton 云量修正 | 原式方向反了（越湿天空应越暖），地表系统性偏冷 5–7 K |
| B1 | `G_dir` 已含 sin(el)，热平衡又乘 cos(θ) | 改用 DNI（法向直射辐照度） | 斜面太阳原来高估 2–5 倍 |
| B3 | 无漫射天空光 | 加 `α·G_dif·vf_sky` | 背阴面白天不再是纯黑 |
| B4 | 金属反射用半球平均 | 逐面视角因子 `vf_sky·L_sky + (1−vf_sky)·B(T_air)` | 裸金属 ε≈0.08，92% 信号来自反射，原来恒等于气温 |
| B5 | NETD 用全局平均 dL/dT | 逐像素 dL/dT | MWIR 在 250→350 K 之间 dL/dT 差 22 倍 |

### 7.2 雷达

| 改动 | 原因 |
|---|---|
| 门限由 `pfa` 反解：`det_db = 10log10(−ln Pfa)` | 手填 `det_snr_db` 掩盖了它隐含的虚警率；Pfa=1e-6 → 11.4 dB，灵敏度与虚警的权衡变成可见参数 |
| 加 Swerling I 起伏（每 CPI 一次 `σ·(−ln U)`） | 确定性 RCS 让检测退化成查表，模型学不到「漏检」 |
| 打开杂波（`clutter_density`） | 原来 `clutter_density=0`，图像里永远没有虚警斑点 |
| 波束栅格按目标张角重算 | 原 0.3°/波束 > 目标 0.19° 张角，目标落在两波束之间，**完全探测不到** |
| 补 `sensors.radar.pos/look_at` | 缺这组键时雷达用默认位姿，指向完全错误的方向 |
| 闭合剖面改 `linear` | smoothstep 在 t=0 处径向速度为 0，每片段第一帧都落在 MTI 盲区 |

### 7.3 激光雷达

雾的消光改用 Kim 分段指数 `β=3.912/V·(λ/0.55)^(−q)`，905 nm 与 550 nm 的能见度不再混用。

## 9. 已知限制（写清楚比藏起来有用）

1. **仍是固定门限，不是 CFAR**。门限由 Pfa 推导，但没有参考单元滑窗，所以杂波边缘的虚警不会随局部功率起伏。
2. **面片 RCS 用功率叠加**。对 cm 级三角网格是对的（相干叠加会输出网格伪影），但对平板/二面角这类强镜面体会低估约 10log10(N)。
3. **杂波只进图像，不产生虚警点迹**。`clutter` 计数恒为 0。
4. **无热惯性**。逐面稳态解，对「车刚停下 / 驶入阴影」这类时序任务是错的。
5. **光学后端的相机位姿**现在是逐帧从清单读取的（之前是静态位姿，和红外/雷达不一致）。
6. **SAR 仍未实现**，仓库名里的 SAR 是路线图。
