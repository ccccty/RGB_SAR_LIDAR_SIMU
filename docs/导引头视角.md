# 导引头视角：平台机动 + 双视场

这一版把「导引头」从**静态靶场**改成了**飞行器视角**，并加了窄/宽两个视场。

旧模式的几何是反的：相机钉在原地，目标被拖着飞过来。于是背景是死的（每帧同一片地面），平台没有地速，MTI 没有东西可抑制，Doppler 与画面互不相干。新模式让相机沿一条真实的**俯冲 + 蛇形**航迹前进，目标基本静止——地速推移、云台滞后、机体横滚、双视场同时成立。

改动只落在 `simkit/motion.py`、`simkit/plan.py`；场景本身由 `tools/make_seeker_scenes.py` 生成（`scenes/sk3_*.json`），本文第 4 节记录的是这四个场景的实测值。旧场景的 `plan` 数值逐位不变。

## 1. `motion.DiveWeave`：解析的平台航迹

```python
DiveWeave(origin, target, speed_mps, heading_deg, dive_deg=-14,
          weave_amp_m, weave_hz, t_end, standoff_end_m=None,
          phase=0.0, target_vel=None, solve="standoff")
```

航向与俯冲角定死一个单位向量 `u`，蛇形加在**水平且与 `u` 严格正交**的方向 `lat` 上（`u·lat == 0`，所以蛇形不会偷走沿航迹速度）：

```
pos(t) = p0 + u·(v·t)      + lat·A·sin(ωt+φ)
vel(t) =      u·v          + lat·A·ω·cos(ωt+φ)      ← 精确导数，不是差分
acc(t) =                    - lat·A·ω²·sin(ωt+φ)
```

- `|vel| = sqrt(v² + (Aω cos)²)`，默认取 `v = sqrt(speed² − (Aω)²/2)`（`solve="speed"` 时），即**均方速度等于配置速度**，瞬时偏差是二阶小量。
- `lateral_accel(t)` 直接给云台/机体的横滚用。

### 终点间距是解出来的，不是凑出来的

`p0`、俯冲角、片段时长都给定了，再要求「`t_end` 时刻距离目标 = `standoff_end_m`」就过约束了，所以**沿航迹速度由几何反解**：终点是航迹线与间距球的交点，是一个二次方程

```
|B + u·x|² = standoff² ,  B = (p0 − target(t_end)) + lat·A·sin(ω·t_end+φ)
x = −(u·B) − sqrt((u·B)² − |B|² + standoff²)        # 取首次穿越
v = x / t_end
```

`standoff_end_m` 缺省或判别式为负（航迹线与球不相交）时退回配置速度，不会炸。实测三个场景反解出的速度与设计值差 ≤ 0.4%：

| 场景 | 设计 v | 反解 v_track | 起点距 / 终点距 |
|---|---|---|---|
| 空中 | 180 | 180.08 | 7280 → 6204 m |
| 地面 | 60 | 60.32 | 2099 → 1757 m |
| 海面 | 120 | 119.44 | 5160 → 4462 m |

解析性验证（`h=1e-5` 中心差分对比 `vel`）：`|v_fd − v_analytic| ≈ 1e-8`，即 `vel` 确实是 `pos` 的导数。

## 2. `ClipPlan(mode="platform")`

`clip.seeker.mode = "platform"` 时：

| 量 | 旧 `seeker` 模式 | 新 `platform` 模式 |
|---|---|---|
| 相机 | 静止（`sensors[*].pos` 固定） | 沿 `DiveWeave` 前进，`sensors[*].pos` 逐帧平移 |
| 目标 | 被拖过来（极坐标插值） | 静止或慢速（`pos + vel·t`） |
| 距离 | `｜target − 静止相机｜` | `｜target(t) − track(t)｜` |
| 背景 | 死画面 | 真实地速推移 |

- **测距**：`range_for_time` 走 `cam_pos_at(t)`，平台模式取航迹点，旧模式仍取 `self.cam_pos`（原路径，数值不变）。
- **云台**：`aim = target_pos(t − lag_s)`，再叠 `wander_deg/wander_hz` 的双正弦漂移，语义与旧模式完全一致（同一套公式、同样的 `0.7×` 俯仰比）。`_basis` 按每个片段自己的视线重建，所以 clip 1 的方位变了，wander 的"右/上"也跟着转。
- **每段不同的交战几何**：同一场景的两段不能是同一段录像。所有定义"这一趟"的量都由片段随机流（`base_seed*104729 + clip*7919 + 17`）抽取：
  - **方位交替**：`heading = heading_deg + (±heading_spread_deg) + N(0, 0.15·spread)`，clip 0 走 −10°、clip 1 走 +10°，两段**必然**差 20° 左右（不是"抽到了才差"）。
  - **斜距**：从场景自己的 `range_m` 区间取，并按片段奇偶分段（偶数段取前 36%、奇数段取后 36%），所以两段起点必定错开，且都在像素带内。
  - **俯仰/俯冲**：`el_deg`（带符号，正=相机在上方，负=在下方向上爬）± 0.8° 抖动，航迹沿视线方向（`dive = −el ± 1°`），闭合速度 ≈ `speed` 而不是变成侧向穿越。`el_deg` 可写在 `clip.seeker` 或 `clip.seeker.platform` 里，seeker 块优先；不写时退回 `|dive_deg|`（≥1°）。
  - **蛇形相位**：随机。
  - 起点由 `origin = target − 视线方向 · r0` 反算，所以改 `range_m` 就是改起始距离；`z` 由 `r0·sin(el)` 得到（空中场景 ≈ 目标上方 1100 m）。
- **横滚**：`roll = bank_max · tanh( atan(a_lat/g) / bank_max )`。`a_lat` 取自 `DiveWeave.lateral_accel`。用 `tanh` 而不是硬 `clip`，是因为硬限幅会把横滚变成方波；`tanh` 小角度线性、接近上限时渐近，既不越界也不是恒零。
- **双视场**：`clip.views` 每项 `{name, tag, fov_deg, width, height, sweep_deg?, sweep_hz?}`。两视场 `pos` 相同，`fov/width/height` 不同；窄视场 aim 指向目标，宽视场在 aim 基础上绕世界竖轴做 `sweep_deg·sin(2π·sweep_hz·t)` 的搜索扫描（缺省 0 = 同向）。

### 新增字段（`state()`）

```python
state["views"] = {
  "seeker": {"pos":[x,y,z], "look_at":[x,y,z], "fov_deg":2.2, "width":960, "height":720,
             "tag":"", "roll_deg":-0.8, "sensor":"ir_camera"},
  "wide":   {"pos":[...],   "look_at":[...],   "fov_deg":18.0,"width":1280,"height":960,
             "tag":"_wide","roll_deg":-0.8,"sensor":"ir_camera"},
}
state["view_px"]      = {"seeker": 45.98, "wide": 7.43}
state["view_range_m"] = 4621.03
```

`views[*]["sensor"]` 是额外字段（契约之外、纯增量），标出该视场取自哪个传感器块，方便导出时决定渲染后端。

`summary()` 每个片段新增：`views`（每视场 fov/width/height/tag/起始与结束像素）、`roll_deg`（横滚区间）、`platform_speed_mps`、`target_speed_mps`、`target_accel_mps2`、`platform`（本段的 `r0_m / heading_deg / dive_deg / el_deg / speed_mps`，用来核对两段是否真的不同）。平台模式下 `speed_mps/accel_mps2` 两列改为描述**平台**（真正运动的那个刚体），目标的速度另给 `target_speed_mps`。

### 向后兼容

无 `clip.views` 时 `views` 只含一项：`{"seeker": {tag:"", 取自 sensors[cam_name]}}`，`fov/width` 与旧 `state` 一致，`roll_deg` 恒 0，`view_px` 与 `target_px` 相等（误差 0）。旧字段（`range_m / target_px / poses / jitter / cfg / weather / clip`）一个没删。

## 6. 遗留问题

1. **横滚饱和**：25 m@0.15 Hz 在 250 m/s 下是 22.2 m/s²（2.3 g），真实协调转弯对应 arctan(22.2/9.81) ≈ 66°，超过 `bank_max_deg=25`，所以 `tanh` 大部分时间贴在 ±25 附近（平顶波）。要平滑正弦横滚，降 `weave_amp_m` 或提高 `bank_max_deg`。
2. **地速推移在 IR 静止帧上看不出来**：相机确实以 100–250 m/s 前进，但地面是单一材质、无纹理，窄视场整幅均匀灰度。要在画面上体现 ground rush，需要渲染侧给地面加纹理/热斑（`ir.py` / `scene.py` 不属本任务文件）。标注层是连贯的。
3. **无地形碰撞/最低高度钳制**：高度只由 `r0·sin(el)` 与俯冲角决定，极端参数下可能穿地，需要场景侧把关。
4. **宽视场扫描只有方位向**：`sweep_deg` 是绕竖轴的单正弦，没有俯仰扫描、没有栅格/螺旋图案。
5. **`range_m` 只在"起点"处生效**：平台模式下它是起始斜距的抽样区间，终点距离是 `r0 − v·(t_end)` 的结果（或 `standoff_end_m` 显式给出时由二次方程反解）。
6. **`sk3_low_air2air_occluded` clip 0 末帧 70.2 px**，比 15–70 的上限高 0.2 px（'目标占宽 7.3%'）。一行修正：把该场景 `range_m` 下界 2000 → 2100，或 `target_m` 5.0 → 4.9。我按文件归属没有改场景生成器。
7. **宽视场的标注框会在小目标上消失**：帧 0 实测 `sk3_high_air2air` 4.2 px → 空框、`sk3_low_air2ground_clutter` 3.8 px → 空框、`sk3_low_surface2air` 4.1 px → 有 10×3 框。目标几何上在画面内（按 `look_at/fov` 投到 (717,493)/(1280,960)），是 `labels.boxes_from_mask(obj_id, world, min_px=8)` 把不足 8 个覆盖像素的目标丢掉了。修法二选一：`min_px` 降到 2–3，或 mask 为空时回落到 `boxes_from_corners`。这将决定宽视场图有没有框，属 `labels.py`/`dataset.py`（主控）。
8. **两段以上的场景**：方位按片段奇偶交替，clip 0 与 clip 2 方位相同（只有斜距/相位/天气不同）。要段段不同需把 `heading_spread_deg` 改成按 `clip % n` 轮转。
