# 整体架构浏览与干扰增广（2026-11-03）

本轮实现的是**通用图像域干扰增广**：有源类为附加噪声和亮斑，无源类为遮挡和对比度衰减。
雷达 RD / RA、SAR 图也支持噪声和对比度扰动。分类表示数据增广类别，不表示发射机、
传播链路或散射体的电磁模型；不提供装备级压制、欺骗或诱饵效能推算。

## 项目浏览结果与接入方式

| 层次 | 现有模块 | 本轮处理 |
| --- | --- | --- |
| 场景与时间 | `scene`、`motion`、`plan`、`weather` | 沿用现有模型、轨迹和片段时间；干扰不改动运动真值 |
| 几何与材料 | `mesh`、`bvh`、`materials`、`spectra` | 保持共享几何，不用显示扰动伪造材质或 RCS |
| 传感器 | Blender / `optical_sensor`、`ir`、`radar`、`lidar`、`sar` | 干净物理输出先完成，再统一产生增广分支 |
| 编排 | `dataset.run`、`dataset.merge_parts` | 配置开启时自动导出；分块完成并合并后只生成一次增广分支 |
| 标签与导出 | `labels`、COCO、`tools/export_yolo.py` | 保留几何框，记录合成遮挡；完全遮挡框从增广 COCO 中移除，YOLO 跳过不可见框 |
| 工作台 | `studio.py`、`studio/index.html`、`studio/app.js` | 增加继承/关闭/有源类/无源类/混合选项，样张可切换 clean / interfered |
| 检查 | `validation`、`tools/check_interference.py`、测试目录 | 参数预检、产物数量与像素检查、HTTP 接口、分块一致性、默认关闭回归 |

核心逻辑集中在 `simkit/interference.py`，没有在五个物理传感器内各复制一套处理。
图像处理只保留当前帧的数组，COCO 检查缓存尺寸而不缓存整段视频的遮挡位图。
同时修复了浏览中发现的 JSON 文件未及时关闭、工作台读取字典框时访问 `boxes[0]`、
默认表单误改独立飞行场景，以及全遮挡数据导出时类别表丢失的问题。

## 可用类型

| kind | 分类 | 作用与限制 |
| --- | --- | --- |
| `additive_noise` | active | 按图像完整码值范围加入高斯噪声，所有栅格模态可用，支持 8/16 位 |
| `glare` | active | 图像坐标中的高斯亮斑，模拟通用过亮/饱和增广；用于 optical / ir / lidar 图 |
| `occlusion` | passive | 可移动矩形覆盖层，透明度可调；用于 optical / ir / lidar 图 |
| `contrast_loss` | passive | 图像向指定底色混合，所有栅格模态可用，包括雷达 RD / RA 与 SAR |

`strength` 为 0–1 的图像码值强度，不是瓦特、J/S 或衰减 dB。
`center_uv`、`size_uv` 和 `drift_uv_s` 使用归一化图像坐标；同视场不同分辨率可使用同样的位置参数，
不同视场下也不宣称对应同一个三维遮挡物。雷达 RD / RA 不接收相机遮挡层，避免混淆坐标域。

事件使用 clip 内的秒数，支持 `start_s`、`end_s` 和平滑过渡 `fade_s`；
不同片段重新按片段时间触发。随机噪声只取决于配置种子、全局帧号、事件 ID 与产品名，
与执行顺序、分块位置无关。

## 配置与运行

默认未配置时关闭，原有生成逻辑不增加增广目录。
安装依赖：`env/Scripts/python.exe -m pip install -r requirements.txt`；新增功能使用 Pillow。

场景中的配置示例：

```json
{
  "interference": {
    "enabled": true,
    "seed": 7,
    "events": [
      {
        "id": "radar_image_noise",
        "kind": "additive_noise",
        "modalities": ["radar"],
        "strength": 0.035,
        "start_s": 0.1,
        "end_s": 0.9,
        "fade_s": 0.1
      },
      {
        "id": "image_occluder",
        "kind": "occlusion",
        "modalities": ["optical", "ir"],
        "strength": 1.0,
        "center_uv": [0.51, 0.5],
        "size_uv": [0.12, 0.45],
        "drift_uv_s": [0.02, 0.0],
        "color": [0.5, 0.5, 0.5]
      }
    ]
  }
}
```

示例场景仍使用用户指定的 `assets/models/军用飞机/双发战斗机.obj`，原始 OBJ 未改动。
在仓库根目录运行（生成验证需使用新输出目录）：

```powershell
# 全流程，默认只生成 10 帧；同时产生干净结果和 interfered 分支
env/Scripts/python.exe -m simkit validate -c scenes/validation_fighter_interference.json -o out/interference_new -s optical,ir,radar,lidar

# 已有数据直接增广，不重复调用 Blender；预设为 off / active / passive / mixed
env/Scripts/python.exe -m simkit augment -i out/validation_interference_10 -o out/interference_new_variant --preset mixed

# 使用自定义场景内的 interference 配置
env/Scripts/python.exe -m simkit augment -i out/validation_interference_10 -o out/interference_custom -c scenes/validation_fighter_interference.json

# 检查增广分支
env/Scripts/python.exe -m tools.check_interference out/interference_new/interfered

# 10 帧的 YOLO 验证导出
env/Scripts/python.exe tools/export_yolo.py --runs out/interference_checks --scenes active,passive --out datasets/interference_checks_10 --min-frames 10 --fmt png --no-compose
```

同一来源的增广目录可以重建；程序只清理上次文件清单中由自己生成的文件。
来源目录、包含来源的父目录或不属于该导出的非空目录均被拒绝作为输出。

## 输出与标签语义

- 干净目录保持原有图像、原始回波、点云、检测结果和几何真值。
- `interfered/` 是可独立导出 COCO / YOLO 的图像分支，包含图像、标签、COCO、帧表、观测参考、元信息与统计。
- `interference.json` 声明 `domain: image_codes`，记录配置、来源、完整文件清单、实际变化帧数和调度帧数；完成状态为 `complete`。
- 帧标签的 `interference` 按产品保存事件来源；`source_visible` 保留原始可见性。
  `synthetic_visibility` 是**几何框覆盖区域内**合成遮挡层透过率的均值，不是按目标轮廓计算的真实遮挡率，
  也不是探测概率。部分遮挡仍使用原有 amodal 几何框；完全遮挡的框不进入增广 COCO / YOLO。
- 雷达 `points`、`boxes_rd` 和三维框仍是干净参考，`detection_scope` 明确说明检测未从扰动图重新计算。
  工作台展示的 SNR/峰值同样来自干净参考。增广分支不复制原始回波与 LiDAR 点云，不宣称它们已被扰动。
- 红外 16 位图保持位深，但归一化增广后的计数不作为新增的绝对辐射标定数据。
- 清洁分支使用 `check_minimal` 做独立实例/深度配准检查；增广分支使用 `check_interference`，
  两项检查的作用域不同。

# 场景级干扰实体（物理层，2026-11-03 第二轮）

上面这一层是**图像域增广**，本文档以下不再改动它：`simkit/interference.py` 保留，
语义仍是"对已渲染的图像叠加效果"，`interference.json` 里仍然是 `domain: image_codes`。

本轮新增的是另一件事：**干扰体作为场景中真实存在的物体**，进入五个传感器的正向模型。
差别不是实现细节，而是能否支撑"干扰是否有效"的问题：

| | 图像域增广（保留） | 场景级干扰实体（本轮新增） |
| --- | --- | --- |
| 数据形式 | 已成像的像素 / 码值 | 场景中的位置、速度、姿态、尺寸、波段、功率 |
| 雷达 | 在 RD 图上叠亮斑或噪声 | 进入回波合成，落在正确的距离-多普勒单元，抬高接收机噪声底 |
| 光学/红外 | 覆盖层、亮斑 | 真实几何体，参与遮挡；红外诱饵是真实自辐射源 |
| LiDAR | 点云图上加噪声 | 参与回波，可产生虚假回波点 |
| 时间 | 事件窗口内强度变化 | 有独立 `pos(t)`、`vel(t)`，可膨胀、可飘移、可拖曳 |
| 标注 | 不产生目标 | `label=False`、`cls="ecm"`，永不进入目标标注框 |
| 能回答的问题 | "图变差了吗" | "噪声底抬高了多少 dB、多出几个假目标、箔条何时失效" |

## 配置

场景 JSON 增加一个与 `interference` 并列的 `ecm` 块。缺省即关闭，
关闭时所有传感器的输出与改动前逐位一致（`tests/test_ecm.py` 有断言）。

```json
{
  "ecm": {
    "enabled": true,
    "entities": [
      {
        "id": "escort_jammer",
        "kind": "noise_jammer",
        "pos": [40, -60, 3005],
        "vel": [200, 0, 0],
        "erp_w": 2.0,
        "jam_bandwidth_mhz": 200,
        "mode": "barrage",
        "band": "Ku",
        "life": { "start_s": 0.0, "end_s": 8.0, "fade_s": 0.05 }
      },
      {
        "id": "repeater_01",
        "kind": "false_target",
        "pos": [0, 0, 3000],
        "count": 4,
        "range_step_m": 210,
        "range_offset_m": 150,
        "power_ratio": 1.6,
        "band": "Ku"
      },
      {
        "id": "chaff_01",
        "kind": "chaff_cloud",
        "pos": [-8, -6, 2998],
        "radius_m": 6.0,
        "growth_mps": 7.0,
        "rcs_m2": 140.0,
        "decay_s": 6.0,
        "fall_mps": 2.2,
        "wind": [6, 0, 0]
      }
    ]
  }
}
```

所有实体共有 `id`、`kind`、`pos`、`vel`、`accel`、`life`、`band`、`visible`、`note`。
未知字段直接报错而不是忽略：静默丢键会让一个场景"看起来在干扰"而参数根本没生效。

### 无源类

| kind | 物理模型 | 关键参数 |
| --- | --- | --- |
| `chaff_cloud` | 偶极子云：半径按 `r0 + growth*t` 膨胀，RCS 按 `(r0/r)^k` 稀释并叠加沉降指数 | `radius_m`、`growth_mps`、`rcs_m2`、`dilution_exponent`、`decay_s`、`fall_mps`、`wind` |
| `corner_reflector` | 三面角反射器，闭式 `sigma = 12*pi*a^4/lambda^2` | `size_m` |
| `decoy` | 拖曳式或抛撒式诱饵，可 `towed_by` 挂在机体后方 `tether_m` 处 | `towed_by`、`tether_m`、`rcs_m2` |
| `infrared_flare` | 红外诱饵：真实自辐射体，温度按 `decay_s` 冷却 | `temp_c`、`decay_s`、`radius_m` |

### 有源类

| kind | 物理模型 | 关键参数 |
| --- | --- | --- |
| `noise_jammer` | 压制式：单程 `R^-2` 链路 + 天线方向图，抬高接收机噪声底 | `erp_w`、`jam_bandwidth_mhz`、`mode`(spot/barrage)、`sidelobe_db` |
| `false_target` | 欺骗式：复制目标真实回波，搬到指定距离/多普勒单元（DRFM 语义） | `count`、`range_step_m`、`range_offset_m`、`velocity_step_mps`、`power_ratio` |
| `range_gate_pull_off` | 距离门拖引：假峰随 `rate_mps` 走离真实距离，饱和于 `max_offset_m` | `rate_mps`、`max_offset_m` |
| `velocity_gate_pull_off` | 速度门拖引：同上，作用于多普勒 | `rate_mps`、`max_offset_mps` |
| `angle_deception` | 角度欺骗：在偏离真实方位的波束注入能量 | `angle_offset_deg` |

压制与欺骗的语义差别是刻意的：无源体和独立辐射体走**两程雷达方程**，在自己的位置上被解算；
转发式欺骗必须**锚定目标回波**，雷达看不见目标时它保持静默——否则会往空帧里凭空造出飞机。

## 物理落点

- **雷达**：`radar_noise_floor` 先算 `pn_beam`（热噪声 + 干扰功率），
  `radar_apply` 再把实体回波追加进回波表，两者都在 `by_beam` 分组之前，
  所以假目标和真实回波经过完全相同的拍频、FFT、检测链路。
  接收机噪声底的改变量与解析 `P_j/pn` 在 1 dB 内一致（测试断言）。
- **光学 / 红外**：实体三角形进入 `world.faces`，因此 rastorizer 的遮挡、深度、
  自辐射全部自动生效；红外诱饵靠材质 `h_int` 成为强红外源。
- **LiDAR**：同一棵 BVH，实体参与回波；箔条云是可穿透体（`pass_through`），
  否则撒箔条会把要保护的目标自己遮没。
- **标注**：所有实体 `label=False`，不进入 COCO / YOLO 目标类。

## 已知近似

- 箔条云当前按**点目标 + 总 RCS** 注入回波，放置于云心，没有沿径向展宽。
  真实云是扩展体，会占据多个距离单元。这一条写在 `simkit/ecm.py` 文件头，
  是下一步的工作，不是遗漏。
- 角反射器闭式 `sigma = 12*pi*a^4/lambda^2`，默认 `a=0.3 m` 在 Ku 波段约 28.8 dBsm
  （`a=0.15` 为 16.8 dBsm，`a=0.5` 为 37.7 dBsm）。它按设计就是要压过目标机体，
  这是器材用途而不是建模偏差，所以没有为了画面好看去调小默认值。演示场景里没有放它。
- 干扰功率按天线方向图的高斯主瓣加旁瓣地板估算，不包含极化失配与多径。
