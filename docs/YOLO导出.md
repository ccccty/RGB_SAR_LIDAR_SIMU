# 导出 YOLO 训练集

`tools/export_yolo.py` 把仿真产物转成 Ultralytics YOLO 能直接吃的检测数据集。
它只做格式转换，不重新仿真；所有几何都来自同一次仿真里同一份三维世界。

```
python tools/export_yolo.py                        # 全部场景，>=60 帧的那些
python tools/export_yolo.py --scenes seeker_air2ground
python tools/export_yolo.py --flavours optical,ir_lwir --fmt png
```

## 1. 为什么按"模态"分成多套数据集

YOLO 一次只在一个图像空间里训练。把 2.2° 导引头帧、18° 搜索帧、中波红外帧混进
同一个 `images/` 目录，等于让网络同时学三种尺度，谁的精度都上不去。

所以输出是：

```
datasets/yolo/
  images/<flavour>/{train,val}/<scene>__f000123.jpg
  labels/<flavour>/{train,val}/<scene>__f000123.txt
  data_<flavour>.yaml        ← 每套一个，直接喂给 yolo train
  classes.txt                 ← 类别名（顺序即 id）
  pairs.csv                   ← 同一时刻各模态图路径（做融合/多分支训练用）
  export.json                 ← 统计与自检结果
```

| flavour | 图像来源 | 分辨率 | 说明 |
|---|---|---|---|
| `optical` | `images/optical` | 768×576 | 窄视场可见光（导引头主镜） |
| `optical_wide` | `images/optical_wide` | 640×480 | 宽视场可见光（搜索镜） |
| `ir_mwir` / `ir_lwir` | `images/ir_preview_*` | 768×576 | 中波/长波红外 8-bit 预览 |
| `ir_mwir_wide` / `ir_lwir_wide` | `images/ir_preview_*_wide` | 640×480 | 宽视场红外 |
| `sar` | `images/sar` | 768×320 起 | 条带 SAR（只有配置了 `sensors.sar` 的场景） |
| `radar_rd` | `images/radar` | 512×256 | 距离-多普勒图，见第 6 节 |

红外用 **8-bit 预览**而不是 16-bit 原始计数：后者是给辐射测量用的，
`Image.open` 读进来是 `I;16`，绝大多数训练脚本会把它错当成 8-bit 直接截断。

`pairs.csv` 是这套导出的关键之一：一行 = 一个时刻，各列 = 该时刻各模态图像路径。
做早期/中期融合、或做"同一目标在不同传感器下"的对照实验时，按这张表对齐，
不要按文件名猜。

## 2. 配准是怎么保证的

"多模态配准"在这份数据里是**构造出来的**，不是事后对齐的：

1. 每一帧只有一个三维世界、一组物体位姿；
2. 每帧的每个视场只有一份相机位姿（`clip.views[name].pos / look_at / fov_deg / roll_deg`）；
3. 所有模态的二维框都由**同一套投影函数**从物体三维包围盒算出来
   （`simkit/labels.py: project_points` → `boxes_from_corners`）；
4. 渲染器自己的 id 掩膜**只用来判可见性**，不参与定框位置。

第 4 点是踩过坑才定下来的：Blender 的 id pass 覆盖整机轮廓（30 px 宽），
而红外的逐面片栅格化会漏掉细长三角面、只框住机身（17 px 宽）。
两边各用自己的掩膜定框时，同一目标在光学和红外里**差 4 px**——
这个位移在世界里不存在，融合训练会把它当信号学走。

导出器每次运行都会自检这一条：对每个时刻、每组共用位姿的模态，
逐对象比较框坐标，把最大偏差写进 `export.json` 的 `registration` 段。
当前实测 **max_dev_px = 0.00**。

### 横滚（这条曾经是错的）

平台蛇形俯冲时云台带 24.7° 横滚。Blender 渲染端一直应用 `roll_deg`，
而 numpy 端的 `sensor_basis()` 没有接收这个参数——红外、雷达、激光、标注投影
全部按水平基向量算。结果：横滚 0° 的帧两路差 0.1 px，横滚 24.7° 的帧**差 40 px**。
`simkit/scene.py` 的 `sensor_basis(..., roll_deg=)` 修好后，宽视场两路输出
逐位一致（325.2, 245.7, 328.2, 247.4 完全相同）。

## 3. 划分：按片段，不随机

每个场景是两段独立的交战（各 120 帧 / 6 秒）。随机切帧会让
t=3.01 s 在训练集、t=3.06 s 在验证集——两帧肉眼几乎一样，
验证分数会变成记忆分数。所以：

- `clip 0`（帧 0–119）→ `train`
- `clip 1`（帧 120–239）→ `val`

两段的初始方位差 ≥20°、斜距差 ≥300 m（`plan.selftest()` 有断言），
所以验证集确实是没见过的几何。`pairs.csv` 的 `clip` / `split` 列可直接核对。

## 4. 类别

类别名取自 COCO 的 `categories`，跨场景统一编号，写在 `classes.txt`：

```
0 uav
1 vehicle
```

（具体内容随场景集合变化；每次导出都会重新算，`export.json` 里有完整映射。）

## 5. 标注口径

- 框 = **物体三维包围盒的投影**，不是可见轮廓。部分遮挡时框仍覆盖整机，
  这与主流检测数据集（COCO/VOC）一致。
- **完全被遮挡**（射线打穿不了）→ 该帧没有这个框，图片照样导出（负样本）。
- **目标在该模态里没成像**（例如宽视场 2.6 px、低于红外探测器采样极限）→
  导出器会把这条标注丢掉，理由写在 `dropped_invisible`：
  一个指向空天空的框教出来的是误检。
- 小目标不做上采样/切图，见下面第 6 条。

## 6. 模态拼接图（每次导出必生成）

导出器默认还会生成三类"同一时刻多模态拼在一起"的图，直接放在 `datasets/yolo/` 下：

| 拼接 | 面板 | 输出尺寸 |
|---|---|---|
| `stack_narrow` | optical + ir_mwir + ir_lwir | 2312×596 |
| `stack_wide` | optical_wide + ir_lwir_wide | 1284×500 |
| `stack_sar` | optical + sar（仅配置了 SAR 的场景） | 1540×596 |
| `stack_radar` | optical + radar_rd | 1284×596 |
| `stack_air` | optical + ir_mwir + radar_rd（三路，最直观） | 1796×596 |

每类出两份，用途不同：

```
datasets/yolo/composites/<stack>/{train,val}/<scene>__f000123.jpg   ← 带面板名和框，给人看
datasets/yolo/images/<stack>/{train,val}/...                        ← 干净，可训练
datasets/yolo/labels/<stack>/{train,val}/...                        ← 各面板的框平移到拼接坐标
datasets/yolo/data_<stack>.yaml
```

- **面板按原始分辨率贴，不缩放**。把 2 px 的目标重采样到统一宽度，就是标注悄悄对不上像素的开始。
- 拼接坐标是纯平移：`x' = x + x_offset`，`y'` 不变，所以标签是精确的，不是估算的。
- 带框那份用三种颜色区分面板，小目标额外画四角括号（2 px 的框在整图缩放下看不见）。
- `data_stack_*.yaml` 可以直接训练——这是最简单的"早期融合"：一张图里放三个已配准的视角。
  注意归一化是在**整张拼接图**上做的，不是单面板。

只重建拼接图（不重导其他模态）：

```
python tools/export_yolo.py --only-compose
python tools/export_yolo.py --no-compose        # 这次跳过
```

### 已知外观问题

SAR 面板里会有方块状纯黑区域：那是物体遮挡后的无回波区，只剩噪底、被 8-bit 显示拉伸压到 0。
真实 SAR 阴影同样是黑的，但这里的边缘偏方正，来自粗网格重采样，不是真实阴影形状。

## 6.5 距离-多普勒图（`radar_rd`）

`images/radar` 是距离-多普勒（RD）图：**横轴 = 距离 0–10.2 km，纵轴 = 径向速度 ±333 m/s**。
一个检测点在图上就是一个单元，所以这里的标注是**点目标框**（3×3 px），不是轮廓框。

导出这路之前修了三处，否则 RD 图是错的：

1. **量程**：`n_samples × c/2B` 曾按 `c/2B` 算，多算一倍；FMCW 实采样下最大不模糊距离是
   `n_s·c/4B`。旧配置 512×30 MHz 只有 2.6 km，9.6 km 的目标被夹到最后一格还"检测成功"。
2. **负频镜像**：实拍差频信号频谱共轭对称，FFT 后半段是镜像。原来两半都留着，
   等于每个目标在图上出现两次，而且距离轴不单调。
3. **多普勒**：原来只算目标自身速度，忽略了平台 200 m/s 的接近速度，目标落在零多普勒
   （正好在 MTI 陷波里）。现已按"相对平台"计算，并让 PRF 与之匹配（chirp 15 µs → ±333 m/s）。

当前工作点（`sk3_*` 场景）：7.5 MHz 带宽、1024 采样、15 µs chirp/pri、256 chirp、
40×28 波束、**2°×6° 笔形波束**、**40 dBm（10 W）** 峰值功率。量程 10.2 km、速度 ±333 m/s。
单帧雷达约 19 s，是整条流水线里最慢的一环。

俯仰波束曾经用默认的 12°，那是搜索雷达的扇区形状；导引头是笔形波束，收窄到 6° 直接换回 6 dB 增益，
比把功率抬到 kW 级更符合物理。

**雷达的检出率是真的会变的，这是特性不是缺陷**：

| 场景 | 目标 | 斜距 | RD 出框 | 检测 SNR |
|---|---|---|---|---|
| 高空空对空 | 飞机 | 7.7–9.6 km | 20/20 | 14–31 dB |
| 低空地対空 | 无人机 | 6.4–5.0 km | 19/20 | 12.5–30 dB |
| 低空空对地 | 0.5 m² 漫游车 | 2.7–1.7 km | 14/20 | 13.7–80 dB |

漫游车那 6 帧是**链路预算真的不够**（0.5 m² @2.6 km、10 W、2°×6°），RD 图上那个格子确实没有亮点，
所以没有框是正确的——不要用几何位置去补标，那是在教模型"看见不存在的东西"。

**一个必须记住的数**：处理增益要算整个二维阵列（`n_samples × n_chirps`），不能只算 chirp 维。
`pn` 用的是 ADC 带宽噪声（`n_samples/chirp_us`），后面的距离维 FFT 属于匹配滤波的一部分。
漏掉 `n_samples` 会让 SNR 凭空低 30 dB——这条 bug 曾经让我把发射功率从 40 dBm 一路抬到 61 dBm
去"够到门限"，其实是在给 bug 做补偿。修好后 61 dBm 是**功率选择**（导弹导引头本来就在 kW 级），
不是补丁。

RD 图另有两处：跨波束是**逐格取最大**（1120 条波束非相干求和会给噪声底加 31 dB，30 dB 的目标
在图上是 1/255、框落在黑格）；单 PRF 下 `v_r` 要折进 ±λ/(4·pri) 再定位框，否则框会贴到 Nyquist 边缘。

## 7. 已知局限（用之前请读）

1. **宽视场目标 2–5 px**，归一化后 w≈0.005。YOLO 在 640 输入下这类目标基本消失。
   宽视场那三套建议：imgsz ≥ 1280，或先切图（tiling）再训，或只当负样本用。
2. **红外宽视场在 8 km 处只有 1 个像元**（已加"亚像元点目标"冲激，
   否则一帧里连一个像素都画不出来）。这类样本适合做"有没有"的点目标检测，
   不适合学形状。
3. **SAR 的几何和光学不同**：侧视条带成像，方位/距离刻度非线性，
   框在世界坐标里对得上，但在图像空间里不能和光学框互换。
4. **空标注帧占比**因场景而异（遮挡场景前 30 帧整段无目标）。
   `export.json` 的 `empty` 字段是真实数字，训练时按需过滤。
5. 图像是 **JPEG q92**（`--fmt png` 可改无损）。红外预览本身就是 8-bit 拉伸结果，
   再压一次会有轻微块效应，对检测影响可忽略。
6. 每场景 240 帧 = 12 秒。够做流程验证和小规模训练，不够训一个通用模型；
   要加量就改 `tools/make_seeker_scenes.py` 里的帧数后重跑。

## 7.5 实测口径（导之前先看这个表）

三个测试场景（各 20 帧）导出的框尺寸中位数：

| flavour | 框数 | 中位框（px） | 最小宽 | 结论 |
|---|---|---|---|---|
| `optical` | 60 | 30.6 × 17.2 | 13.3 | 可训练 |
| `optical_wide` / `ir_*_wide` | 各 60 | 3.1 × 1.7 | 1.3 | **不可训练**，只当搜索阶段样本 |
| `radar_rd` | 60 | 3.0 × 3.0 | 3.0 | 点目标，可做"有无"检测 |
| `sar` | 20 | 3.0 × 4.0 | 3.0 | 点目标，且**序列准静态**（见下） |

**宽视场为什么这么小**：视场是窄视场的 8–10 倍，分辨率反而更低（640×480 vs 768×576）。
目标在 0.3%–0.9% 画幅，物理上就 1–3 px。要变成可训练样本得把宽视场提到 2560×1920 量级，
不是调个参数的事。当前保留它们作为"搜索阶段"的真实分布，不作为默认训练集。

**SAR 为什么是准静态**：`dataset.py` 让 SAR 每帧把波束对准目标（否则平台 180 m/s 的位移会把目标
推出方位窗），代价是目标在图上几乎不动——20 帧里只漂 2–3 px，帧间差异主要是斑点噪声。
正确做法是加宽 `az_extent_m` 让目标自然扫过，而不是逐帧重新对准；这条没做。

## 8. 训练示例

```bash
pip install ultralytics
yolo detect train data=datasets/yolo/data_optical.yaml model=yolov8n.pt imgsz=768 epochs=50
yolo detect train data=datasets/yolo/data_ir_lwir.yaml model=yolov8n.pt imgsz=768 epochs=50
```

多模态融合训练不在本仓库范围内，但 `pairs.csv` 提供了严格对齐的配对关系，
按它组织 dataloader 即可（同一行 = 同一时刻 = 同一目标位置）。
