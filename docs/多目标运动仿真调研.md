# 多目标运动仿真调研：相对轨迹、抛放物动力学与一致性约束

> 本文只做调研与方案，不涉及代码改动。第 1 节先把三个症状翻译成可测量的几何量，第 2–4 节给
> 业界做法与物理数字，第 5 节给数据结构与 `pos(entity, t)` 伪代码，第 6 节给按性价比排序的改动清单。

## 0. 结论先行

1. **业界没有「多目标各自独立绝对轨迹」的编队做法。** 协议层（DIS/HLA）只传绝对状态 + 外推；
   工具层（VR-Forces、AFSIM、SIMbox）把编队实现为「长机状态 + 每个成员相对长机的偏移」，
   偏移是**派生量**，不是权威状态。权威状态永远是绝对位姿，因为只有它能被网络传播、被外推、被记录。
2. **抛放物没有「长期跟随」。** 抛出即转为独立实体：初态继承载机（位置 + 速度 + 弹射矢量），
   随后气动阻力把**相对气团的速度**拉到 0，剩下的位移来自载机自己飞走。唯一的例外是牵引式诱饵
   （系绳约束），那是另一类实体。
3. **症状 1/2/3 的共同根因不是路径公式，而是「参照系不统一 + 状态源不唯一」。** 主目标的世界位置
   是 seeker 反解的派生量（由像素/距离要求反解出来），副目标与干扰体却按场景里另写的绝对
   `pos + vel*t` 走。两者没有共享的父状态，分离速率就是两者速度之差，任何「把两条路径都调好看」
   的做法都不会收敛。
4. **「箔条飞离目标几百米」要拆开看。** 箔条本来就该脱离：它停在气团里，载机以 200 m/s 飞走，
   2 s 就是 400 m。这是物理正确的。错的是它脱离的**方向与速率来自一个与主目标无关的速度**
   （场景里另写的 180 m/s），于是它往侧后方「飘走」，而不是沿载机航迹「掉队」。
   红外诱饵弹的几百米滞后则两者都有（自身减速 + 载机飞走）。
5. **时间尺度差两个数量级。** 单体箔条：末速 0.3 m/s，特征滑行距离 `L = v_t²/g ≈ 1 cm`，
   毫秒级停住。箔条云（整包）：成云 < 1 s、直径约 30 m，工程上按 0.5–2 s 随气团。诱饵弹：
   `L ≈ 50–120 m`，5 s 落后 150–300 m，燃烧 ≥ 3.5 s。
6. **推荐用两个物理参数描述抛放物**：相对气团的初速 `v_rel0` 与特征滑行距离
   `L = 2m/(ρ C_d A) = v_t²/g`。二次阻力下 `τ_q = L/|v_rel0|`，
   `位移 = L·ln(1+t/τ_q)`，`速度 = v_rel0/(1+t/τ_q)`，位置/速度/加速度全闭式、C∞、可分块。
   现有的一阶滞后 `rel_decay_s` 可保留为工程近似，但 τ 必须按 `L/v_rel0` 标定，现行 2.5/3.0 s
   大了一个数量级以上。
7. **一致性判据要能自动跑**：单实体包线（已有）+ 跨实体几何（新）+ 抛放物时序（新）+
   传感器同源（原则已有，缺断言）。第 4 节给 21 条，每条带公式、阈值和落点。

## 1. 症状的几何诊断

### 1.1 主目标在 seeker 模式下没有「场景速度」

`plan._plan_seeker` 之后，主目标的世界位置不是场景写的，而是反解出来的：

```
p_t(t) = p_c + u(az(t), el(t)) · r(t)
v_t(t) = u · ṙ + r · (∂u/∂az · ȧz + ∂u/∂el · ėl)
```

`_seek_state`（simkit/plan.py）就是这么算的，导数闭式，这是对的——`docs/运动修正报告.md` 记的那次
「首帧半速 / 76.9 g」就是在这里把钳位参数拿去差分造成的。

问题在于**这个速度的量级和方向由像素预算决定，而不是由气动决定**：

| 输入 | 典型值 | 对 v_t 的贡献 |
|---|---|---|
| `target_px` 8–45 px | 决定 r 的窗口 | 无（只定 r） |
| `closing_mps` 缺省 `0.25·(hi-lo)/dur` | 8 km 带、4 km 宽、5 s → 200 m/s | 径向 |
| `az_span_deg` 1.2° | 8 km 处 167 m / 5 s | 切向 33.5 m/s |
| `el_span_deg` 0.5° | 8 km 处 70 m / 5 s | 纵向 14 m/s |

也就是说主目标的世界速度可以是 30 m/s，也可以是 200 m/s，取决于这个镜头要多大的像素跨度。
而副目标的速度是场景作者按「看起来像飞机」写死的 180–250 m/s。**两者之差就是画面上的分离速率**：

```
分离速率 = |v_sub - v_main|，2 s 后间距 = 2·|v_sub - v_main|
```

`v_sub = 180 m/s`、`v_main = 40 m/s`（默认 span 的小场景）→ 2 s 后 280 m；在 8 km / 1.2° 的
画幅（横向仅 167 m）里，副目标 0.5 s 就出画。这看起来正是「一个不动、一个飞走」。

**结论：这不是轨迹调参问题，是参照系问题。** 只有当副目标的速度**由主目标派生**（编队偏移的导数，
或抛放后继承主目标速度再衰减），它才可能一直同框。

### 1.2 干扰体：绝对坐标 + 与 clip 无关的时间

`ecm.entities_at`（simkit/ecm.py）当前是：

```
pos = pos0 + vel·t + 0.5·accel·t²
vel = vel0 + accel·t
chaff: pos += (wind + (0,0,-fall))·t ;  vel += 同项
```

三个问题：

1. **`vel0` 与主目标无关。** `scenegen._complete_entity` 里写的是 `vel = site['unit']·speed`
   （沿初始视线方向 180 m/s 之类）。主目标被 seeker 拖去另一个方向，干扰体还沿原方向飞，
   于是 3 s 就是 500 m 的横向分岔——不是「掉队」，是「分道扬镳」。
2. **漂移用绝对 `t` 而不是 `age = t - life.start_s`。** 抛放延迟 2 s、`fall = 1.5 m/s` 时，
   实体在第一帧就有 3 m 的位置偏移和 1.5 m/s 的速度偏移。速度项直接进 Doppler：
   X 波段 1.5 m/s ≈ 100 Hz，足以改变一个距离-速度单元。
3. **加速度项 `0.5·accel·t²` 没有物理来源。** 抛放物在气动阻力下是减速的，不是恒加速的。

### 1.3 已经出现的「半个修法」及其缺口

代码里已经有 `parent / rel_pos / rel_vel / rel_decay_s`（`ecm.entities_at` 与
`scenegen._complete_entity`），方向是对的：用相对量描述伴随体。但有五个缺口：

| # | 缺口 | 后果 |
|---|---|---|
| a | `vel = host_vel + rel_v·e^{-t/τ}`，载机速度永不衰减 | 箔条永远保持载机速度 → 实际是「编队飞行」，不是抛放；雷达 Doppler 上箔条和载机同速，脉冲多普勒无法区分 |
| b | 相对位移有界：`rel_v·τ`（如 6 m/s × 2.5 s = 15 m） | 真实抛放物相对载机的位移**无界**（载机继续飞），所以它永远贴着目标 15 m，看起来像挂在机翼上 |
| c | `rel_pos/rel_vel` 用世界轴（`site.unit`/`site.perp`） | 载机转弯 30° 后，挂点还在原来的世界方位上，箔条从机腹「甩」到机背 |
| d | 漂移从 `t=0` 起算 | 见 1.2 第 2 条 |
| e | 拖曳诱饵分支直接 `pos = host_pos - v̂·tether_m`、`vel = host_vel` | 没有系绳方向滞后、没有下垂、没有拖曳体自身阻力；载机一转弯诱饵瞬移 |

另有两条**跨传感器不一致**（不在 `ecm.py` 的数学里，而在调用点）：

- `ecm.render_objects(cfg, t=0.0)` 调 `entities_at(spec, t)` **不传 anchors**，而
  `dataset.py` 调它时**也不传 t**。于是光学（Blender）通道里，所有抛放体都停在
  **t=0 的绝对坐标**上，每一帧都不动；而雷达/红外/激光雷达走 `attach`/`_prepare`，是带
  anchors、按帧时间求值的。同一颗诱饵弹在照片里和雷达里不是一个位置。
- `anchors_of(world)` 从渲染世界对象取位姿，是**第二条状态通路**：主目标的位置在
  `plan` 里算一遍、在 `world.objs` 里再存一遍、在 ECM 里再读一遍。三条通路只要有一处没同步，
  就出现「照片里在 A、雷达里在 B」。

> 代码可能正在被并行修改（`ecm.py` 的 `parent` 分支就是新加的）。上表按当前工作区状态记录，
> 落地前需复核一次。

### 1.4 手绘轨迹模式

`view.trajectory.mode = "drawn"` 时（`scenegen`），主目标改飞操作者画的世界折线，
`speed_mps` 由操作者给；`studio._trajectory_smooth` 只做「这条折线飞不飞得动」的可行性拟合
（限 1.5 g、按 `v²κ` 反解速度），**不检查它与伴随体的关系**。而副目标、干扰体仍是各自的绝对直线。

于是手绘模式把 1.1 的问题放大了：主目标可以突然 90° 转向，伴随体毫无反应；
画得越自由，关系越荒诞。**手绘应当是「长机路径」**，其余实体从它派生——这与 AFSIM 把
route（航路）与 mover（相对/编队运动器）分开、VR-Forces 把队形定义为「名字 + 相对长机的偏移表」
是同一个设计。

## 2. 业界做法：相对轨迹 vs 绝对轨迹

### 2.1 协议层（DIS / HLA）：只传绝对状态，相对关系是应用层的事

**DIS（IEEE 1278.1）** 的 Entity State PDU 携带的是**地心（ECEF）绝对**位置、速度、姿态，
外加 dead-reckoning 参数。接收端不外推「父子」，只按 DR 算法外推绝对状态。一致性在协议层的
定义是「外推误差不超过阈值」，不是「几何上属于同一编队」：

- IEEE 1278.1-1995 §5.1.4 定义了方向阈值、位置阈值与心跳计时器；
- 常见实现默认值：方向 3.0°、位置 1.0 m、心跳 5 s（开源实现 disorder 的 `defaults`，
  注释明确写「exercise defaults from IEEE1278.1-1995 section 5.1.4」）。
- DR 算法族（DRM_FPW/RPW/RVW/FVW…）全部作用在**单个实体**的绝对状态上，没有一个算法接受
  「另一个实体」作为输入。

**DIS 7 的 Entity Association 可变参数**是标准里唯一接近「挂接」的表达：它带
`association type`、`associated entity ID`、`own station location`、`physical connection type`、
`group member type`（见 MAK VR-Link 的 `DtEntityAssociationVPRecord` 字段表；Open-DIS 的
`EntityAssociationVP` 同构）。含义是：**子实体声明「我挂在谁身上、挂在哪个站位」，
但它仍然发布自己的绝对状态**。这正是拖曳诱饵/挂载物在标准里的写法，也是我们
`towed_by + tether_m` 想表达的东西。

**HLA / RPR FOM（SISO-STD-001）** 同理：`BaseEntity` 的空间属性是世界坐标；聚合体用
`AggregateEntity` 表达；时间管理服务（TAR/TAG/LBTS）保证联邦内同一时间基准。
标准把「相对」完全留给应用层。

> **可迁移的结论**：绝对状态必须是权威（可外推、可记录、可跨进程），相对结构只能是
> **生成绝对状态的机制**。我们的 `ClipPlan` 恰好相反——主目标的绝对状态是派生结果，
> 却没有任何东西把它登记为「权威」，于是伴随体只能各自猜。

### 2.2 工具层：编队 = 命名队形 + 长机偏移表

| 产品 | 原语 | 偏移/约束 | 关键事实 |
|---|---|---|---|
| **MAK VR-Forces 5.x** | `formationUtils` 队形定义 | 每个 subordinate 一个 `VectorOffset3D`，「offset is the offset to the formation leader」；`fillFormationOffsetObjectMap`、`getPlatformOffsetsFromUnit`、`bCenterFormation`（以包围盒中心为基准） | 偏移是**按名字查表**得到的派生量；`DtFormationState::DerivedOffsets` 的命名本身就是「派生」 |
| **AFSIM 2.9** | 每种运动一个 mover | `WSF_OFFSET_MOVER`：`reference_platform` + `offset_x/y/z`；`WSF_FORMATION_FLYER`；`WSF_TOWED_MOVER`（拖曳）；`WSF_HYBRID_MOVER`（路由/跟随可切换） | 平台的运动方式由 mover 类型决定，「相对」是一种 mover，不是全局坐标约定；`WSF_AIR_MOVER` 的 `turn_rate_limit`/`bank_angle_limit`/`default_radial_acceleration` 决定僚机「跟得多紧」 |
| **SIMbox（Simigon）** | `AircraftFormation` 逻辑组件 | 属性 `PROP_IS_LEADER`、`PROP_LEADER_NAME`、`PROP_OFFSET_FROM_LEADER_X/Y/Z`、`PROP_NUMBER_IN_FORMATION`；属性 `ATT_FORMATION_DISTANCE_TO_POSITION_IN_FORMATION` | 成员知道自己「是谁的几号僚机、偏多少」，这是最直白的产品化表达 |
| **JSBSim** | 一个 FDM 实例 = 一架飞机 | 无编队原语 | 六自由度积分是单体问题；多机 = 多实例（VirtualAir 的 HLA 集成说明：multiple aircraft can be simulated by executing multiple JSBSim instances） |
| **FlightGear** | AI 对象 + flightplan 航点 | 无编队原语 | AI 对象按航路点飞，可挂内部 FDM；编队靠外部脚本/航路设计 |
| **OpenEaagles** | Simulation / AirVehicle 组合框架 | 无编队原语 | 蜂群/编队以**扩展**形式出现（SwarmSim 即「An OpenEaagles Framework Extension for HIL Swarm Simulation」） |

两种实现风格值得注意：

- **AFSIM 风格**：把「相对」做成 mover 的一种，和「按航路飞」并列。好处是同一个平台可以在
  不同阶段切换（`WSF_HYBRID_MOVER` 就是为此存在），坏处是每种组合要一个类。
- **VR-Forces 风格**：把「相对」做成一张队形表（名字 → 偏移集合），实体只持有 `(formation, index)`，
  运行期查表。好处是队形可复用、可编辑；坏处是偏移不能随时序演化（要演化就得换队形或加 behavior）。

我们要的是两者的交集：**实体持有 `(parent, offset, 演化规则)`，演化规则是少量闭式函数。**

### 2.3 相对偏移如何随时间演化：三档

| 档位 | 数学形式 | 物理含义 | 出处/证据 |
|---|---|---|---|
| **刚性保持**（rigid） | `offset` 在长机机体系为常量，世界偏移 = `R_L(t)·o_b` | 理想僚机；实际靠闭环修正，受转弯率/坡度限制，转弯时外扩 | AFSIM `WSF_FORMATION_FLYER`；formation control 文献的「rigid formation」（Appl. Sci. 13:5934 综述：刚性队形的相对距离不可变） |
| **滞后跟随**（lagged） | `o(t)` 用长机的**延迟姿态**：`R_L(t-τ_lag)·o_b`；或一阶滤波 | 僚机必须先滚转再拉杆，转弯时切内角；稳态转弯有固定角滞后 | 滞后量由 `turn_rate_limit`/`bank_angle_limit`/气动时间常数决定（AFSIM 参数表；JSBSim 六自由度） |
| **各自机动**（free） | `o(t) = o_b + m(t)`，`m` 是自身机动（有界） | 僚机在队形内做机动，或脱离队形执行任务 | AFSIM `WSF_HYBRID_MOVER`（路由/跟随切换）；formation control 的「flexible formation」（相对距离可变）与 position/displacement/distance 三类（Automatica 2015 综述） |

滞后跟随的量化（本文推导，用于设阈值）：

```
协调转弯角速率      ω = g·tan(φ)/v
稳态角滞后          Δψ ≈ ω·τ_lag
横向队形误差        e ≈ R·ω·τ_lag        （R = 队形间距）
```

代入 5 g @ 200 m/s：`ω = 9.81·√(25-1)/200 = 0.24 rad/s = 13.8°/s`；`τ_lag = 0.3 s` →
`Δψ = 4.1°`；`R = 200 m` → `e = 14 m`。这个量级就是「队形看起来散了但没散」的合理范围，
也是判据 C5 的来由（超过 `R·ω·τ_lag` 的 2 倍就是几何错误，不是滞后）。

### 2.4 一次性抛放物：抛出即独立，没有长期跟随

- **标准层**：DIS 的 Entity Association 仍要求子实体发布自己的绝对状态；没有「跟随」语义。
- **工具层**：AFSIM 用独立的 `WSF_TOWED_MOVER` 表达「拖曳」，其余抛放物就是普通平台 +
  初态继承；DSIAC 的 FLAME（Flare Aerodynamic Modeling Environment）把
  「投放器位置/朝向 + 抛放图样 + 气动」作为输入，弹道是独立解算的——这正是「抛放物是独立实体」的
  产品化证据。
- **物理过渡**（三段，见第 3 节）：

```
t < t_r     附着：p = p_p(t) + R_p(t)·m_b                 （挂点，随机体系转）
t = t_r     继承：p = p_p(t_r) + R_p(t_r)·m_b
             v = v_p(t_r) + R_p(t_r)·v_eject_b            （初速 = 载机速度 + 弹射速度）
t > t_r     独立：v_rel_air(t) 按阻力衰减到 0，叠加风与重力
```

关键点：**「相对载机的位移」必然无界**（载机继续以 200 m/s 飞），所以「在目标周围」只在
抛放后 1–2 s 内成立。想让它多出现几帧，正确的旋钮是**抛放时刻、抛放方位、载机速度、视场**，
不是把它的速度写小。

## 3. 抛放物的物理：从随动到独立

### 3.1 初速（文献值）

| 对象 | 数值 | 出处 |
|---|---|---|
| 红外诱饵弹弹射速度 | **26–54 m/s** | Chemring 58550 数据表（280 g 装药、峰值 20 kW/sr、最短燃烧 3.5 s、反作用力 2.5 kN） |
| 诱饵弹口径/装药 | 2×1×8 in 方形药柱，MTV（镁/特氟龙/氟橡胶） | MJU-7A/B 公开数据（GlobalSecurity、ARM-TEC、Ordtech 的等效型号页） |
| 箔条成云 | 释放后**不到 1 s 形成约 30 m 直径的云** | 美国空军 1997 年说明，经 DTIC 环境评估附录 A 引用 |
| 箔条沉降末速 | **约 0.3 m/s** | 美国空军环境说明（「settling velocity of approximately 30 cm per second」）；Barr 1963（JGR）《Terminal fall velocity of radar chaff》给出定量方法 |
| 箔条阻力 | 13 种偶极子构型的落塔/风洞测阻 | DTIC ADA019525《Chaff Aerodynamics》 |

### 3.2 时间尺度：单体、云、弹三者差两个数量级

抛放物相对气团的运动方程（NEXRAD 箔条落速报告里就是这一条）：

```
m·dv/dt = -½·ρ·C_d·A·v·|v| - m·g·ẑ + 风项
```

一维（沿相对速度方向）有闭式解，定义两个量就够：

```
特征滑行距离   L = 2m/(ρ·C_d·A) = v_t²/g
特征时间       τ_q = L/|v_rel0|
速度           v(t) = v_rel0/(1 + t/τ_q)
位移           x(t) = L·ln(1 + t/τ_q)
加速度         a(t) = -v²/L
```

| 对象 | 质量/迎风面积（量级） | `v_t` | `L` | `τ_q` @200 m/s | 90% 减速耗时 | 5 s 自身位移 |
|---|---|---|---|---|---|---|
| **单体箔条**（25 µm × 15 mm 铝） | 2.0e-8 kg / 3.8e-7 m² | 0.33 m/s（低 Re，`C_d≈8`） | **1.1 cm** | 5.6e-5 s | < 1 ms | ~5 cm |
| **箔条云**（整包，含未炸开的包体与遮蔽） | 包体为主 | 0.3–1 m/s（沉降） | **5–40 m**（默认取 10 m） | 0.03–0.2 s | 0.25–1.8 s | 12–90 m |
| **红外诱饵弹** | 0.35–0.5 kg / 0.005–0.01 m²，`C_d≈1.2` | 20–25 m/s | **50–120 m** | 0.25–0.6 s | 2.3–5.4 s | 150–300 m |

说明（重要，避免误用）：

1. **单体与云差 5 个数量级是真实的**，原因不是公式错：单体箔条的迎风面积/质量比 ≈ 19 m²/kg，
   而诱饵弹 ≈ 0.025 m²/kg。单体确实在毫秒内停住。
2. **雷达看到的是云的质心，不是单体。** 成云过程中包体未炸开、云内偶极子互相遮蔽、湍流混合，
   都让「云」的有效 `L` 从厘米级抬到米级。工程上常用的说法是「1–5 s 内降到风速」
   （RF Essentials 的 EW 知识库，属经验值），对应 `L ≈ 20–110 m`；本文取 5–40 m 作为
   图像仿真够用的区间，默认 10 m。**这个参数应当显式暴露并可标定，而不是藏在代码里。**
3. **诱饵弹的几百米滞后是物理正确的**，不是 bug：`L = 55 m`、`v0 = 200 m/s` 时 5 s 落后 162 m，
   再加上弹射的侧向分离与下坠，画面里就是「几百米」。若场景要求它别跑远，只能减少 clip 时长、
   提前抛放或加大视场。

### 3.3 简化模型选型

| 模型 | 公式 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **二次阻力（物理型）** | 见 3.2 四式 | 参数有物理意义（m, A, C_d）；速度衰减先快后慢，符合实测；闭式 C∞ | `x(t)` 对数发散，必须靠寿命截断 | **推荐**。实现只需两个参数 `L`、`v_rel0` |
| **一阶滞后（工程型）** | `v = v_rel0·e^{-t/τ}`，`x = v_rel0·τ(1-e^{-t/τ})` | 位移有界、天然 C∞、导数简单；就是现有 `rel_decay_s` 的形式 | 5 s 滞后比二次阻力低估 2–3 倍；`τ` 无直接物理意义 | 保留接口，`τ` 按 `τ ≈ 3–5·τ_q` 标定（对齐 5 s 点），或直接换二次式 |
| **常速 + 线性漂移（现状）** | `x = v0·t + drift·t` | 无 | 把「减速」整个丢掉；漂移与速度重复计数 | 淘汰 |

一阶滞后与二次阻力的换算（本文推导）：令两者 5 s 位移相等

```
τ_q·ln(1 + 5/τ_q) = τ·(1 - e^{-5/τ})
```

`τ_q = 0.25 s`（诱饵弹）→ `τ ≈ 0.83 s`（比值 3.3）；`τ_q = 0.05 s`（箔条云）→ `τ ≈ 0.24 s`
（比值 4.8）；`τ_q = 0.6 s` → `τ ≈ 1.6 s`（比值 2.7）。**结论：现有 `rel_decay_s` 的
2.5 s（箔条）/ 3.0 s（诱饵）应降到 0.2–0.3 s / 0.8–1.6 s**，否则抛放物看起来像挂在翼下。

### 3.4 垂直与漂移

- 垂直：`v_z(t) = -v_t·tanh(g·t/v_t)`（二次阻力精确解）。`v_t = 0.3 m/s`、clip ≤ 12 s 时，
  用常值 `-v_t` 的误差 < 2%，可以直接取常值。
- 风：`v_air(t) = wind(t) + (0, 0, -fall)`。位移要用**解析原函数** `A(t) = ∫v_air`；
  常值风就是 `A(t) = v_air·t`。风随时间演化时（`weather.clip_states` 已经是 t 的函数），
  用它的解析积分或至少同一采样，别在位置里用 `wind·t`、在速度里用 `wind(t)`——那是两个故事。
- 寿命：燃烧/散开/落地 → `life.end_s` + `fade_s`。寿命外不要继续积分（现在会，因为位置是 t 的
  无界函数）。

## 5. 工程方案

### 5.1 唯一状态源：`Track`

所有实体、ECM、传感器、标注只从一个东西取状态：

```python
class Track:                     # t -> (p, v, a)，解析、C∞、与分块无关
    pos(t) -> (3,)
    vel(t) -> (3,)
    accel(t) -> (3,)             # 解析或对解析 v 中心差分（h=1e-3）
    frame(t) -> R(3,3)           # 机体系→世界系，与 yaw/pitch/roll 同一套定义
```

- seeker 模式：`track_target = Track(_seek_state)`；`accel` 由 `v` 的闭式再求导，或对解析 `v`
  中心差分（`h=1e-3`，误差 O(h²)，远小于 B3 阈值）。
- platform / world / drawn 模式：`track_target = Track(path.pos/vel/accel)`。
- **`anchors_of(world)` 退休**：ECM 的父状态直接取 `track_target`，不再经过 `world.objs`。

这一步是「症状 1/2 的 80%」：一旦副目标和干扰体都能拿到主目标的当前状态，它们就自动
「跟得上」；剩下的只是各自的相对规则。

### 5.2 实体 schema

```jsonc
{
  "name": "wingman_1",
  "kind": "aircraft",            // aircraft | chaff_cloud | infrared_flare | corner_reflector | decoy | jammer
  "link": "formation",           // independent | formation | released | towed

  // ---- 通用
  "body": { "model": "...", "size_m": 19.0, "yaw_mode": "velocity" },
  "envelope": { "cls": "fighter" },

  // ---- link = formation
  "formation": {
    "parent": "target_0",
    "offset_body": [-120.0, 60.0, -15.0],   // 父机体系：后、右、下（m）
    "mode": "lag",                          // rigid | lag | free
    "tau_lag_s": 0.3,                       // 只用父机姿态的滞后，不用位置的滞后
    "own_maneuver": null,                   // 可选：机体系内有界相对机动（如 Weave）
    "max_offset_m": 500.0                   // 硬限，防止场景写飞
  },

  // ---- link = released
  "release": {
    "parent": "target_0",
    "t_s": 2.0,                             // 抛放时刻（clip 内）
    "mount_body": [-8.0, 1.5, -1.0],        // 挂点/投放器位置（父机体系）
    "eject_body": [0.0, 18.0, -12.0],       // 弹射速度（父机体系，26–54 m/s 量级）
    "drag": { "mode": "quadratic",          // quadratic | lag
              "L_m": 10.0,                  // 特征滑行距离（箔条云 5–40，诱饵 50–120）
              "tau_s": null },              // lag 模式下用它（≈3–5·L/v0）
    "air": { "wind_mps": [5.0, 0.0, 0.0], "fall_mps": 0.3,
             "fall_mode": "const" }         // const | tanh（tanh 用 v_t = sqrt(g·L)）
  },

  // ---- link = towed
  "tether": { "parent": "target_0", "length_m": 90.0, "tau_s": 0.2, "droop_deg": 3.0 },

  // ---- link = independent
  "trajectory": { "mode": "line", "origin": [...], "vel": [...] },

  "life": { "start_s": 0.0, "end_s": 6.0, "fade_s": 0.1 }
}
```

设计要点：

- `link` 是判别式，决定 `pos()` 走哪条分支；四类实体共用同一个接口。
- **挂点、弹射矢量都在父机体系里**（修 1.3 缺口 c）。世界系挂点只在 `R_p` 里出现一次。
- 抛放物只需要 `L`（或 `tau`）一个动力学参数；`v_rel0` 由继承得到，不是作者填的。
- `life.start_s` 与 `release.t_s` 分离：前者是「什么时候可见」，后者是「什么时候脱离」。

### 5.3 `pos(entity, t)` 伪代码

```python
def state(entity, t):
    """-> (p, v, a, yaw). 所有分支都是 t 的解析函数。"""
    if entity.link == "independent":
        return entity.path.state(t)

    P = STATE_OF[entity.parent]                 # 递归调用同一函数（父必须无环）

    # ---------------- 1) 编队成员 ----------------
    if entity.link == "formation":
        f = entity.formation
        R_now  = P.frame(t)                     # 当前机体系
        R_lag  = P.frame(t - f.tau_lag_s)       # 滞后机体系（只滞后姿态）
        o      = f.offset_body
        if f.mode == "rigid":
            p = P.pos(t) + R_now @ o
            # 速度 = 父速度 + ω×R·o（ω 由 R_now/R_lag 的角速度给出）
            w = angular_velocity(P, t, f.tau_lag_s)
            v = P.vel(t) + cross(w, R_now @ o)
        elif f.mode == "lag":
            # 位置仍钉在父机上（队形距离不漂），但偏移方向滞后 → 转弯切内角
            p = P.pos(t) + R_lag @ o
            v = P.vel(t) + cross(angular_velocity(P, t, f.tau_lag_s), R_lag @ o)
        else:                                   # free：自身机动叠加
            p = P.pos(t) + R_now @ (o + f.own_maneuver.pos(t))
            v = P.vel(t) + R_now @ f.own_maneuver.vel(t) \
                         + cross(angular_velocity(P, t, f.tau_lag_s), R_now @ o)
        return p, v, differentiate(entity, t), P.yaw(t)

    # ---------------- 2) 抛放物 ----------------
    if entity.link == "released":
        r  = entity.release
        tr = r.t_s
        if t < tr:                              # 释放前：严格附着
            p = P.pos(t) + P.frame(t) @ r.mount_body
            v = P.vel(t) + cross(angular_velocity(P, t, 0.0), P.frame(t) @ r.mount_body)
            return p, v, differentiate(entity, t), P.yaw(t)

        # 释放瞬间的状态（常量，与 t 无关，可缓存）
        pr    = P.pos(tr) + P.frame(tr) @ r.mount_body
        vair  = air_velocity(tr, entity)                      # wind(tr) + (0,0,-fall)
        vrel0 = P.vel(tr) + P.frame(tr) @ r.eject_body - vair  # 继承 + 弹射，相对气团

        u = t - tr
        if r.drag.mode == "quadratic":
            L    = r.drag.L_m
            tq   = L / max(norm(vrel0), 1e-9)
            s    = L * log1p(u / tq)                          # 自身位移（有界增长）
            frac = 1.0 / (1.0 + u / tq)                       # 速度衰减系数
        else:                                                 # lag（现有 rel_decay_s）
            tau  = r.drag.tau_s
            s    = tau * (1.0 - exp(-u / tau))
            frac = exp(-u / tau)

        p = pr + (A(t) - A(tr)) + vrel0 * s                   # A = ∫v_air（解析）
        v = air_velocity(t, entity) + vrel0 * frac
        return p, v, differentiate(entity, t), atan2(v[1], v[0])

    # ---------------- 3) 拖曳诱饵 ----------------
    if entity.link == "towed":
        tw = entity.tether
        # 系绳方向用「延迟的父速度方向」+ 下垂角；给一阶滞后即 C∞
        u_hat = -normalize(P.vel(t - tw.tau_s))               # 拖在后方
        u_hat = rotate_down(u_hat, tw.droop_deg)
        p = P.pos(t) + u_hat * tw.length_m
        v = P.vel(t) + cross(angular_velocity(P, t, tw.tau_s), u_hat * tw.length_m)
        return p, v, differentiate(entity, t), P.yaw(t)

    # ---------------- 4) 主目标（seeker 反解）----------------
    # 由 Track 提供：p = cam + u(az,el)·r，v = u·ṙ + r·(u_az·ȧz + u_el·ėl)
```

辅助函数：

```python
def air_velocity(t, e):     return wind(t) + [0, 0, -e.air.fall_mps]
def A(t):                   return integral_of_wind(t) - [0, 0, e.air.fall_mps] * t
def differentiate(e, t, h=1e-3):        # 只对解析 v 差分，不对位置差分
    return (state(e, t + h)[1] - state(e, t - h)[1]) / (2 * h)
```

退化检查（这三条是单元测试的核心）：

- `L → 0`（或 `tau → 0`）时，`s → 0`：抛放物立刻停住，`p` 恒等于 `pr`，`v` 恒等于 `v_air`。
- `wind = 0, fall = 0` 时，`A ≡ 0`：只剩弹射位移。
- `t < tr` 时，`p, v` 与「编队成员 + 0 偏移」完全一致（E1 自动成立）。

### 5.5 测试

- **单元**：四类实体各一条导数契约（`|v - dp/dt| ≤ 1e-3`）、释放点 C⁰、`τ→0` 退化、
  `wind=0` 退化、寿命窗口外不参与。
- **场景级**：A1/A3 + C1–C6 + E1–E7 全量跑，输出 `motion_report.json` 的一个新段
  `cross_entity`，与现有 `envelope_violations` 并列。
- **确定性**：同一帧在「整段 / 两分块 / 三分块」下逐位一致（已有 check 3，扩到新实体）。

## 6. 我们该改什么（按性价比排序）

| # | 改动 | 解决什么 | 工作量 | 风险 |
|---|---|---|---|---|
| **1** | **引入 `Track` 作为唯一状态源**：`plan` 暴露 `track(name)`，`object_state`、`ecm.entities_at`、`anchors_of`、`render_objects` 全部改走它；顺手修 `render_objects(cfg)` 不传 t/anchor 的跨通道不一致 | 症状 1 的 80%、症状 2 的方向错误、F4 | 0.5 天 | 低（纯重构 + 一个 bug 修复） |
| **2** | **抛放物改「release 锚定 + 气团松弛」**：`v` 从 `host_vel + …` 改成 `v_air + v_rel0·衰减`；位移改成 `A(t)-A(tr) + s(u)`；`rel_decay_s` 默认值降一个数量级（箔条 0.2–0.3 s、诱饵 0.8–1.6 s） | 症状 2 的物理正确性；E3/E4/E5；多普勒不再和载机同速 | 0.5–1 天 | 中（改数值会改变现有场景外观，需重跑对照） |
| **3** | **副目标改 `formation`**（rigid + 姿态滞后），去掉「未配置就直线」的缺省 | 症状 1 的另一半；C1–C6 | 0.5 天 | 低 |
| **4** | **挂点/弹射矢量改机体系**（`R_p` 只出现一次），加 `tau_lag` 与 `droop` | 1.3 缺口 c；转弯时箔条从机腹甩到机背 | 0.5 天 | 低 |
| **5** | **跨实体检查器**：C/E 两组判据接进 `validate --dry-run` 与 `motion_diagnose`，输出 `cross_entity` 段 | 把「看起来不对」变成数字；防回归 | 1 天 | 低 |
| **6** | **手绘模式改「长机路径 + 派生伴随体」**：`drawn` 只作用于 leader，其余实体走 2 的 formation/released；UI 提示同框预算 C6 | 症状 3 | 2–3 天 | 中（涉及 studio/scenegen 的语义） |
| **7** | **拖曳诱饵系绳动力学**：方向一阶滞后 + 下垂 + 自身阻力 | 拖曳诱饵瞬移 | 2 天 | 低（场景少） |
| **8** | **六自由度/气动积分** | 无（对本项目是负收益） | 2 周+ | 高 |

排序理由：1 是**所有**后续改动的地基（没有唯一状态源，2/3/4 都会各写一遍）；2 是**唯一**
能让干扰体在物理上站得住的改动；3 是症状 1 的直接答案；5 之所以排在 6 前面，是因为
没有判据，6 改完也无法确认「关系不混乱了」。

三条**不要做**的事：

1. **不要为了让箔条「留在目标附近」而调小它的速度。** 它本来就该脱离；调小速度只会让它在
   多普勒上和载机同速（更假）。
2. **不要给每个实体各写一条「看起来对」的绝对轨迹。** 这正是当前症状的来源，且不可复用。
3. **不要在 `pos` 里用 `wind(t)·t` 而在 `vel` 里用 `wind(t)`。** 位置和速度必须是同一函数的
   `f` 与 `f'`，否则 B3 的导数契约会在抛放物上重新破功（`docs/运动修正报告.md` 第 1 节
   已经因为同类问题吃过一次亏）。

## 附录 A　三个数值算例（本文推导，假设写在式子里）

**A.1 单体箔条**（X 波段半波偶极子）

```
l = 15 mm, d = 25 µm, ρ_Al = 2700 kg/m³
m = ρ·π/4·d²·l = 1.99e-8 kg
A = d·l = 3.75e-7 m²
低 Re（Re ≈ 0.5）取 C_d ≈ 8：
v_t = sqrt(2mg/(ρ_air·C_d·A)) = sqrt(2·1.99e-8·9.81/(1.2·8·3.75e-7)) = 0.33 m/s
L  = v_t²/g = 0.011 m
τ_q(200 m/s) = L/v0 = 5.6e-5 s
```

与实测 0.3 m/s 的落速一致（美国空军环境说明）。**单体不是可仿真的对象**：它毫秒级停住，
雷达看到的是云的质心。

**A.2 箔条云**（取 `L = 10 m`，`v_rel0 = 200 m/s`）

```
τ_q = 10/200 = 0.05 s
t = 1 s : x = 10·ln(21) = 30.4 m,  v = 200/21 = 9.5 m/s
t = 5 s : x = 10·ln(101) = 46.1 m, v = 200/101 = 2.0 m/s
```

自身位移 30–46 m；而载机 5 s 飞 1000 m，所以**相对载机的间距 ≈ 950 m**。
「几百米」在 2 s 时就出现（400 − 37 = 363 m）。这不是 bug，是 `v_p` 的积分。

**A.3 红外诱饵弹**（`m = 0.4 kg`，`A = 0.01 m²`，`C_d = 1.2`，`v0 = 200 m/s`）

```
v_t = sqrt(2·0.4·9.81/(1.2·1.2·0.01)) = 23.3 m/s
L  = 545/9.81 = 55.6 m
τ_q = 55.6/200 = 0.278 s
t = 1 s : x = 55.6·ln(4.60) = 84.5 m,  v = 200/4.60 = 43.5 m/s
t = 5 s : x = 55.6·ln(19.0) = 163 m,   v = 200/19.0 = 10.5 m/s
```

垂直方向 2.4 s 后接近 20–23 m/s 的下坠速度，5 s 下落约 90 m。加上 26–54 m/s 的弹射，
5–6 s 时它在载机后下方 200–300 m——这就是真实现场的样子。
