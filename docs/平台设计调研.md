# 平台设计调研：参数分箱、引擎参数口径与数据集说明字段

> 定位：本文只回答四个可直接落地的问题——**界面该分成哪几个箱、每箱放什么、默认值取多少、数据集说明必须写什么**。
> 关于用 REA/Ghidra 处理闭源商业件的正当性与边界，已在 docs/需求与方案_v1.md 第 6 节与 docs/合法软件与数据库调研.md 第 5 节定论（结论：参数与数据有边际价值，逆向求解器不划算）。本文继承该结论、不再复述，也不再把"逆向"当作设计依据；下文所有参数语义均来自公开手册、公开源码与官方文档。
> 现状基线：studio/index.html 在 5 个 details 分组下平铺了 **34 个数值/枚举控件 + 7 个策展式按钮组**（共 41 个可交互项），从"场景选择"到"随机种子"一条直线读下来，任何一次生成都要在"视场—SAR—轨迹—天气"之间来回跳。

---

## 0. 先说三个会被反复引用的判断

1. **参数不是按"功能相似"分组的，按"谁产生这个量"分组。** Rendered.ai 的 node schema 把每个输入口挂在产生它的节点上，SE-WORKBENCH 把材质属性挂在材质编辑器而不挂在传感器上，两边给出的是同一条规则。我们的"收纳箱"必须服从这条规则，否则箱内一定会出现"这个值其实归上一箱管"的争议。
2. **高级参数不是"藏起来"，是"默认值必须有物理出处"。** DIRSIG 敢把采样数藏进命令行、把孔径藏进 Advanced 页，是因为每个参数的默认值都在手册里写死了来源（最小路径数 20、最大 100、材质双面默认 FALSE）。没有出处的高级参数，藏起来就是埋雷。
3. **数据集说明的字段清单不是写作问题，是采集问题。** DIRSIG 的 truth collector 之所以能列出 materialindex / temperature / abundance / 收敛状态，是因为渲染时顺手就把它们算出来了。字段清单必须反过来约束生成器的输出契约，否则事后补不出来。

## 1. 同类软件怎么组织参数

### 1.1 DIRSIG 5：用"文件种类"当分层，用"编辑器分页"藏高级

DIRSIG 是四家里分层最硬的：**一层一个文件类型，层与层之间只靠 ID 引用**。

| 层 | 载体 | 管什么 | 不该管什么 |
|---|---|---|---|
| 场景层 | .scene（XML，classicscene 元素） | 场景原点（WGS84 经纬高 → 局部 ENU）、几何列表（GLIST/ODB）、材质库文件名、检索目录、map 列表、landmark、plume、任意 metadata 名值对 | 不含任何几何顶点、不含任何光学属性 |
| 几何层 | .gdb / OBJ | 三角面、法线、UV、面到材质 ID 的映射 | 不含温度、不含发射率 |
| 材质层 | .mat（tag+value 文本） | MATERIAL_ENTRY：NAME/ID/EDITOR_COLOR/DOUBLE_SIDED/BACK_MAT_ID/THICKNESS + SURFACE_PROPERTIES（发射率/反射率/透过率）+ BULK_PROPERTIES（吸收/散射/相函数）+ RAD_SOLVER + TEMP_SOLVER | 不含空间位置 |
| 大气层 | .atm（四曲线/新大气两种工具链）、.wth 天气 | 逐波长透过率、路径辐亮度、廓线；天气驱动项（THERM/NSRDB） | 不含传感器 |
| 平台/运动层 | .ppd（通用平台位置）、flex motion、mounts | 位置/姿态时间序列、载荷安装关系、指向 | 不含光学 |
| 采集层 | .jsim 插件图 / BasicPlatform | instrument（多焦平面）→ focalplane → capturemethod（simple/raw/lidar）→ imagefile | 不含场景 |

**每层管什么的边界非常干净**，值得直接抄的两点：

- **材质只描述"这是什么物质"，不描述"它多热"。** 温度由 TEMP_SOLVER_NAME 单独指定，默认无求解器即不发光。这解决了我们现在的混装问题：internal_heat 现在混在材质里，导致"同一种涂装换个内热源就要复制一份材质"。
- **三属性不必给全，缺的由已有项推导。** 手册原文：非透射面通常只给发射率或反射率其一，另一个被推导出来；透射面至少要两项。这是"最少必填"思想的现成依据——材质卡片的基础项只应有 3 个格子（发射率、反射率或 albedo、粗糙度），其余折叠。

**默认值怎么给**：全写在手册参数表里，逐项标注 (Default: …)，且默认值本身是物理选择而非 0。材质 DOUBLE_SIDED 默认 FALSE（省一次背面求交）；采集输出的通量单位默认 watts、面积单位默认 cm2；入瞳产物默认是**谱积分辐亮度** W/(cm²·sr)；保真度三个参数默认分别是**最小路径 20 / 最大路径 100 / 谱辐亮度收敛阈值（单位 W/cm²/sr/µm）**。手册还专门解释了"为什么最小值不是 1"——单样本蒙特卡洛估计会得到极噪图像。这句话应原样变成我们滑杆的 tooltip。

**高级参数怎么藏**：靠**编辑器分页 + 插件化**，不靠折叠面板。

- Instrument Editor 的 **Advanced 页**放 aperturediameter / aperturethroughput / focallength；
- Focal Plane Editor 的 **Clock 页**放 temporalintegration 的积分时间；
- Simple Capture Editor 的 **Output Files 页**放 fluxunits / areaunits；
- 再往上一层的高级能力（自定义大气、光源、云、MuSES 耦合）根本不进 GUI，而是以插件形式挂在 .jsim 图里。

**它把辐射链路拆成了三段显式物理量**，这是本文后面分箱的直接依据：
入瞳谱辐亮度 L [W/(cm²·sr·µm)] →（孔径/焦距/透过率定义 G#，G# = (1 + 4·F#²)/(τ_A·π)，F# = f/D_A）→ 焦平面辐照度 E = L/G# [W/cm²] →（时域积分）→ 能量 [J] 或电子数 →（探测模型）→ DN。并且输出 ENVI 头里**强制写入** data units 字段。我们要在数据集说明里报"辐射单位"，依据就在这。

### 1.2 SE-WORKBENCH：一套场景参数，两个计算核

OKTAL-SE 的公开资料把工作台描述为五类数据：**几何、物理材质与纹理、大气、热定义、轨迹**，落到产品上是四段流水：

| 段 | 工具 | 管什么 |
|---|---|---|
| 环境/材质 | SE-AGETIM + SE-PHYSICAL-EDITOR | 由 GIS/地图/3D 模型生成地形，给面赋物理属性；材质是**跨域一份**（IR + 电磁 + 声学统一格式 + API），不是每个传感器各存一套 |
| 场景编排 | SE-SCENARIO | 对象、传感器、事件、大气、路线**同时**在一个场景里管理；这是"事件表"而非"参数表" |
| 计算核（高保真） | SE-RAY-IR | 0.4–15 µm 光谱光线追踪，逐波长求解 |
| 计算核（实时） | SE-FAST-IR | GPU 实时红外，同一场景、同一套物理材质 |

**这里的设计要点比参数本身更重要**：同一个场景参数可以喂给"慢而准"和"快而粗"两个核，用户不需要维护两套配置。我们现在的"预览 8 帧小样 / 生成数据集"两个按钮背后是同一套参数，方向是对的，但缺一个显式的"精度档"参数来声明这次用的是哪一档——这必须是数据集说明的必填字段（见 §3）。

**默认值策略**：OKTAL-SE 把默认值放在"物理属性库"里（材质库带默认热/光学参数），场景侧几乎不给默认——因为战场场景没有"通用默认"。对我们的启示：**材质与大气可以有库默认，场景与轨迹不该有默认**（现在的 scenes/*.json 自动扫描正好符合这条：场景必须是选出来的，不是默认出来的）。

**高级参数怎么藏**：材质编辑器承担了绝大部分复杂度（多层/复合材料、下垫面如混凝土下的沙层）；渲染精度、光线密度这类参数留在 SE-RAY 内核侧；实时核干脆不暴露这些参数。

### 1.3 SensorVision / Ondulus：实时约束下，参数必须压到"一屏装得下"

SensorVision 是 Vega Prime 的运行时传感器模块（IR/NVG/雷达），产品线已于 2023-10-31 起停售、2024 年底实体停止运营，直接手册已不可得；但它的架构与其后继 Ondulus 系列一脉相承，可归纳为四层：

| 层 | 形态 | 说明 |
|---|---|---|
| 材质编码库 | 外部数据（材质分类工作流 + 材料编码） | 支撑"基于物理的波传播、反射与衍射建模"；用户可用自己的数据替换默认数据 |
| 大气 | **独立离线模块** | Vega Prime 的大气模块是一个离线 GUI 工具，先算出大气量再给运行时用——不是运行时逐像素算辐射传输 |
| 传感器定义 | 运行时可编辑的紧凑参数集 | 光学（焦距/视场/孔径）、探测器（像元、波段、积分时间）、电子学（增益/偏置/AGC）合成一份"传感器定义" |
| 后处理效应 | 渲染后叠加 | 噪声、模糊（MTF）、眩光/bloom、暗角、二次反射；Ondulus NVG 明确可配"光放大、NVG 颜色、数字缩放" |

**关键结论（对我们最有用的一条）**：实时档的传感器参数必须能**一屏装下**，因为它是运行时参数而不是离线批处理参数。它的"高级能力"不是再加控件，而是**换数据文件 / 写 GPU 着色器**——开放架构允许开发者替换默认数据甚至自写 shader。

Ondulus IR 的物理描述项也值得抄：探测器分**热型与光子型**两类，热载荷要考虑**辐射负荷、冷却、传导、对流、蒸发**，波段可选**短/中/长波**，支持复合材料与层状材料（地面 + 下垫层）。我们的红外箱目前只有 NETD 与波段，缺"探测器类型"与"冷却/热载荷"这两项，而它们直接决定红外图像的低频非均匀性。

### 1.4 Rendered.ai：参数归属于节点，分组靠 category，默认只在"没连线"时生效

Rendered.ai 的 Graph 画布把参数组织问题回答得最彻底：

- **图 = 程序**：graph 是 YAML（version: 2），顶层只有 nodes 与 nodeLocations。节点有输入口/输出口，输入口要么**直接赋固定值**，要么**连到别的节点的输出**。
- **参数挂在节点上**：每个 node 有一个同名 schema 文件（YAML），列出 inputs（name/description/default/select）与 outputs（name/description），外加 tooltip / category / subcategory / color。**category 与 subcategory 只决定"添加节点"菜单里的归位**，不影响执行。
- **默认值的语义很精确**：schema 里的 default 只在"该口既没被赋值也没被连线"时生效。而且 GUI 里手填的固定值在底层是**字符串**，类型转换由节点自己负责——这条提醒我们：箱内的数值控件必须在 schema 层声明类型与量纲，不能靠前端 input 的 type="number" 兜底。
- **高级参数怎么藏**：节点可以有多输入口，默认只填必填口；select 把枚举做成下拉；tooltip 承载解释；真正的专家路径是**直接手写 YAML 图**，绕过 GUI。这是我们"高级页 + 配置文件双向可编辑"的原型。
- **产物层**：channel（应用）→ package（节点包）+ volume（静态资产，如 3D 车模）→ dataset job（一次批量产出）。"数据集"是 job 的产物实体，带自己的元数据，不混在节点参数里。

### 1.5 横向对比与一句话结论

| 维度 | DIRSIG 5 | SE-WORKBENCH | SensorVision/Ondulus | Rendered.ai |
|---|---|---|---|---|
| 分层单位 | 文件类型 | 工具链阶段 | 运行时数据块 | 节点 schema |
| 参数归属 | 层内自洽，跨层靠 ID | 场景编排统一持有 | 传感器定义集中 | 谁产生挂谁 |
| 默认值出处 | 手册逐项标注 | 物理属性库 | 内置名义参数集 | schema default，仅缺省时生效 |
| 高级藏法 | 编辑器分页 + 插件 | 留内核侧 | 换数据/写 shader | 多输入口 + 手写 YAML |
| 精度切换 | 命令行参数（路径数） | 换计算核 | 无（实时固定） | 换节点 |

**我们该分成哪几个箱（一句话）**：按"物理量在哪一层产生"切，分成 **场景与目标 / 环境与大气 / 传感器组 / 平台与轨迹 / 求解与质量 / 产物与标注** 六箱；任务级元信息（数据集名、随机种子、场景模板、精度档）不进任何箱，作为常驻的"任务头"。这六箱正好与既有架构判断（一个物理状态机 + 三个前向模型 + 一条标注链）一一对齐，不多不少。

## 2. 开源引擎逆向：读源码得到的具体口径

> 方法：只读 GitHub 上的单文件（raw/api），不 clone 整仓。下面每个数值都是从源码或源码内嵌文档串里直接读出来的，不是推测。

### 2.1 radarsimpy（雷达：波形、噪声、检测门限）

**波形层（Transmitter）**——用"频率端点 + 时间端点"描述波形，而不是"波形类型"枚举：

| 参数 | 语义 | 默认值 |
|---|---|---|
| f | 单值 = 单音；[f_start, f_stop] = 线性调频；一维数组 = 任意波形（须配 t） | 必填 |
| t | 脉冲时间（s）；任意波形时是时间轴 | 必填 |
| tx_power | 发射功率 dBm | 必填 |
| pulses | 脉冲数 | 必填 |
| prp | 脉冲重复周期；可为逐脉冲数组 | **缺省 = pulse_length**（即占空比 100%） |
| channels[].polarization | 极化矢量 | [0,0,1]（垂直） |
| channels[].azimuth_angle / elevation_angle | 方向图角度轴 | [-90, 90] |
| channels[].azimuth_pattern / elevation_pattern | 方向图（dB） | [0, 0]（全向） |
| channels[].grid | 场景占用初判的角栅格 | 1 度 |
| channels[].delay | 发射延时 | 0 |
| channels[].pulse_amp / pulse_phs | 逐脉冲幅度/相位编码 | 1 / 0 |
| pn_f / pn_power | 相位噪声频点与功率谱 | None（关闭） |

**接收机层（Receiver）**——把 dB 与电压连起来的三个默认值：

| 参数 | 默认值 | 说明 |
|---|---|---|
| fs | 必填 | 采样率；samples_per_pulse = int(pulse_length × fs)，代码专门处理了浮点边界（fs = N/20e-6 会算出 N−1e-13） |
| noise_figure | **10 dB** | 噪声系数 |
| load_resistor | **500 Ω** | 功率→电压的负载电阻 |
| baseband_gain | **0 dB** | 基带增益 |
| bb_type | complex | 复数/实数基带 |
| gate_delay | **0 s** | 去斜参考延时；文档明说为 0 时长距离目标会**混叠**（6e12 Hz/s 斜率下 111 km 目标拍频 4.45 GHz），并给出 gate_delay = 2R/c 的换算 |

**系统层（Radar）**：frame_time 默认 0；location / speed / rotation / rotation_rate 全默认 (0,0,0)；rotation 用 **[yaw, pitch, roll]**（度）；seed 可选但存在，用于噪声复现。

**检测层（processing）**——门限不是参数，概率才是：

- cfar_ca_1d(data, guard, trailing, pfa=1e-5, axis=0, detector='squarelaw', offset=None)
- offset=None 时按 2T·(Pfa^(−1/(2T)) − 1) 自动算（平方律），线性检波器取平方根；T = trailing
- OS-CFAR 走 cfar_os_1d(data, guard, trailing, k, pfa=1e-5, …)，k 必须在 [trailing, 2·trailing]
- DOA 系列 spacing 默认 **0.5**（波长归一化间距）

**我们该借什么、为什么**：

1. 波形箱用"频率端点 + 时长 + PRP"表达，别用"波形类型"下拉。这样 FMCW、脉冲、任意调制共用同一条代码路径，也天然覆盖我们缺的"频段预设"——预设只是一组端点与 PRP 的命名组合，不是新代码。
2. 检测箱的对外参数是 **Pfa + 保护单元 + 参考单元**，门限 dB 是**派生只读量**。我们现在让用户直接填门限，导致数据集说明里写不出"这批数据的 Pd/Pfa"，而 §3 会看到这正是审查方第一个要问的。
3. 噪声箱必须同时出现 noise_figure（10 dB 量级）与 load_resistor（500 Ω）：只给 SNR 的模型无法解释"为什么同一 SNR 下换基带类型图像噪点不一样"。
4. gate_delay 的文档写法是范本：**先说默认值，再说默认值在什么情况下会坏，最后给换算式**。这条规则应写进我们的参数 schema（每个高级项都要有 risk 字段）。

### 2.2 Mitsuba 3（渲染：环境贴图/HDRI 怎么接、BSDF 参数）

**环境贴图（envmap）**：

| 参数 | 语义 | 默认 |
|---|---|---|
| filename / bitmap | 辐亮度值图像，**必须是等距柱状（latitude-longitude）格式**；二者互斥 | — |
| scale | 对图像辐亮度整体乘的系数 | **1.0** |
| to_world | 发射体→世界变换（可动画） | 恒等 |
| mis_compensation | 为多重要性采样做补偿分 | **false** |

实现细节里有一条对我们很关键：载入后位图会被 pad_to(2, 3) 扩展到 2:3 宽高比（再用 halo 处理），也就是说**它对"等距柱状"的宽高比是有硬要求的**，不符合的贴图会被静默补齐而不是报错。我们的"环境箱"接 HDRI 时必须自己做等距柱状校验并给出提示，否则用户会得到一张"看起来对、辐亮度总量偏了"的天空。

**BSDF 默认值（三家共用的物理常数口径）**：

| BSDF | 参数 | 默认值 | 备注 |
|---|---|---|---|
| roughconductor | distribution | ggx | 备选 beckmann |
| | alpha / alpha_u,alpha_v | **0.1** | 用 alpha 时等价于两者同值；alpha_u/alpha_v 必须成对，且不能与 alpha 同时给 |
| | material | Cu（走 material 分支时） | 也可直接给 eta/k |
| | specular_reflectance | **1.0** | |
| | sample_visible | **true** | |
| dielectric | int_ior | **bk7 = 1.5046** | 可写材质名或数值 |
| | ext_ior | **air = 1.000277** | |
| | specular_reflectance / specular_transmittance | **1.0 / 1.0** | 文档原文：为物理真实起见**不应改动** |
| roughplastic | alpha | **0.1** | |
| | int_ior | **polypropylene = 1.49** | |
| | diffuse_reflectance | **0.5** | |

**alpha 的物理解释被写进了文档**，可以直接拿来当滑杆刻度：alpha 是微面**斜率均方根**，0.001–0.01 对应"表面完好、仅有轻微瑕疵"，0.1 对应"比较粗糙"，0.3–0.7 对应"极粗糙（蚀刻或研磨面）"。我们现在的材质卡片只有"粗糙度 0–1"一个无量纲数，恰好可以把这个语义移植过去：**默认 0.1、三档锚点 0.01 / 0.1 / 0.5**。

**我们该借什么、为什么**：

1. 环境光用 scale 做辐亮度缩放，不要让用户去改 HDRI 像素值——这是"一个物理旋钮替代一堆图像处理"的范例。
2. 材质的默认值给**真实物质的实测常数**（BK7 1.5046、空气 1.000277、聚丙烯 1.49），不给 0 或 1 这种"看起来中性"的值。理由很实际：0 会让菲涅尔项消失，用户拿到的第一张图就是错的，然后他会怀疑整个渲染器。
3. specular_reflectance 这类"能量守恒修正项"默认 1.0 且文档写明**不要动**——我们对应的是"发射率缩放""反射率增益"这类会破坏能量守恒的项，应当放进高级页并标注同样的警告。

### 2.3 lowtran / ThRend（大气与热红外：输入输出约定）

**lowtran 的调用契约**（Python 封装，直调 Fortran lwtrn7）：

- 标量输入默认全 0：h1, h2, angle, im, iseasn, ird1, range_km, zmdl, p, t；wmol 默认 **12 个 0**（12 种气体的柱量）；h1 必须给出有限值（手册 Table 14 要求）。
- **wlstep 默认 20 cm⁻¹，低于 5 会崩**（代码里 logging.critical 提示"最小分辨率 5 cm⁻¹"）；波长上下界由 nm2lt7 换算成 cm⁻¹，并用 ceil 取点数。
- model / itype / iemsct 必须显式给：示例里 model=5（亚寒带冬季）、itype=1（水平路径）/ 3（观测者→太空）、iemsct=0（透过率）/ 1（热辐亮度）/ 2（散射辐亮度）/ 3（太阳辐照度）。
- **输出是一个 xarray.Dataset**，维度 (time, wavelength_nm, angle_deg)，变量恰好四个：transmission、radiance、irradiance、pathscatter。波长由 LOWTRAN 的 µm 乘 1000 转成 nm。

**ThRend 的输入约定**（C++/Embree 的热红外渲染器，纯文本配置）：

- 材质文件（materials）：每条 name + UCD_id + normal_emissivity + diffuse_fraction + roughness；roughness = −1 表示**纯漫反射**；也支持 emissivity_curve（**91 个值，从 90° 到 0° 观察角的发射率曲线**）。实例值：木材 ε=0.95 / 漫反射比 0.9 / 粗糙度 0.0995；沥青 0.92 / 0.70 / 0.0995；玻璃 0.92 / 0 / 0.0141。
- **天空不是一个模型，而是一张表**：tsky 文件就是 **10 个天空亮温值**（示例 256.2 … 285.2 K），运行时按角度插值。整个场景的辐射传输被压缩成这张表。
- 视图设置（viewSettings）：cameraCenter/Direction/Up、fovVertical（垂直视场角）、imageWidth/Height、aa（每像素主光线数，示例 16）、reflSamples（每像素反射线数，示例 100）、MAX_BOUNCES（≥1，小于 1 会被警告并夹到 1）、tmin/tmax 与 tmin_reflected/tmax_reflected（色标范围，示例 10–40 ℃ / −10–30 ℃）。

**我们该借什么、为什么**：

1. **大气箱的输出契约照 lowtran 抄**：不是"能见度"一个数，而是 (波段 × 角度) 上的四个量——透过率、路径辐亮度、太阳/天空辐照度、路径散射。我们现在的 atmosphere.py 只吐一个 tau 常数，三个前向模型各拿各的，必然出现"光学觉得天亮了、红外觉得天没亮"。
2. **天空可以退化成查表**：ThRend 用 10 个数就撑起一个红外场景。环境箱高级项应当允许"外部亮温表"入口，把辐射传输从交互回路上摘掉——这也是离线部署场景下唯一现实的做法。
3. **材质给"发射率曲线"而不是单一 ε**：91 个点覆盖 90°→0°，因为红外里 ε 随观察角变化是肉眼可见的（尤其金属与水面）。我们的材质结构里必须留这个可选槽位，否则掠射角的舰船/海面会系统性偏亮。
4. **色标范围是参数**：tmin/tmax 属于"产物箱"而不是"传感器箱"，因为它决定的是人看到的图，不影响物理量。现在我们把两者混在 ir.py 里，是渲染与可视化没解耦。

## 3. 顶刊顶会的合成数据质量共识

### 3.1 SPIE Defense+Commercial Sensing 一线：验证的对象是"物理量"，不是"像不像"

DIRSIG 的验证与确认（V&V）系列是这一支最完整的公开记录，从 1992 年"屋顶实验"到 2007 年热偏振验证，共 13 项。它们的分析口径高度一致，只有五类：

| 口径 | 具体做法 | 可迁移到我们的指标 |
|---|---|---|
| 绝对温度对比 | 24 小时逐小时成像，场景内 12 个物体贴热电偶，模型温度 vs 实测温度 | 红外 ΔT 偏差（K）与 RMSE |
| 绝对表观温度 | 中波与长波两路分别比 | 分波段表观亮温误差 |
| **对比度排序** | 不比绝对值，比"谁比谁亮"的排序一致性 | 目标/背景对比度秩相关 |
| 摄影测量几何 | 真实与仿真影像的同名点投影与畸变比对 | 重投影误差（px）、框对齐率 |
| 光谱现象学 | 与 HYDICE/SEBASS 高光谱仪对比 | 谱形相似度 |

它给出的两条结论比指标更值钱，并且直接推翻一种常见做法：

- **"场景几何的重要性高于模型精细度"**，且日出日落过渡时段尤其敏感；
- **"最优天气与材质参数 vs 通用参数"的差异是可测量的**——也就是说，数据集说明里必须写清材质与天气是"实测标定"还是"库默认"，否则同一份数据无法被别人复现或对比。

### 3.2 CVPR/ICCV：合成数据的合法性建立在"域间距 + 下游收益"上

首届 SynData4CV（CVPR 2024，Seattle）把议题明确列为三件：**合成与真实的域间距（domain gap）、合成生成带来的偏差、以及合成训练模型的可泛化性**。ICCV 2023 BRAVO workshop 的合成数据采集论文更进一步——它用"无监督域适应的下游性能"来给每一张合成图**定价**，即指标必须落到任务上，而不是停在图像统计。

这意味着数据集说明必须同时给出两件事，缺一不可：

- 一个**分布距离**（图像的 FID/KID、特征的 MMD），用来说明"合成分布离实拍有多远"；
- 一个**下游数字**（仿真训练 → 实拍测试的 mAP），用来说明"这份数据到底有没有用"。既有 P4 验收指标（光学 SSIM、红外 ΔT ±2 K、雷达 RCS ±3 dB、终极指标是 mAP）与这条共识一致，需要补的只是把"分布距离"显式化。

### 3.3 多模态数据集的文档实践：逐传感器写，写到能重放

nuScenes（CVPR 2020）与 Waymo Open Dataset（CVPR 2020）确立的多模态文档骨架是：**每个传感器单独给规格（型号、波段/激光波长、线数、视场、帧率、分辨率）→ 标定（内参 + 各传感器到车体的外参）→ 时间同步与时间戳策略 → 标注统计（类别、数量、尺寸分布、遮挡/截断定义）→ 场景划分与地理/天气覆盖**。这套骨架之所以成为事实标准，是因为缺任一项，别人就无法把你的数据接进自己的训练管线。

配套的通用文档规范提供字段的"元结构"：Datasheets for Datasets（CACM 2021）分七部分（动机、构成、采集、预处理/清洗/标注、用途、分发、维护）；Data Cards（FAccT 2022）强调可追溯的模块化卡片。我们要生成的 数据集说明.md 应当能被机器填满，因此字段必须按这三份规范的并集设计，而不是按我们自己的目录结构设计。

### 3.4 各模态的验收指标口径（写进说明文档的那几个数）

| 模态 | 指标 | 口径与出处 |
|---|---|---|
| 光学 | SSIM、色彩分布 KL、FID/KID | SSIM：Wang 等，IEEE TIP 2004；FID 出自 Heusel 等关于双时间尺度更新规则的论文（NeurIPS 2017） |
| 红外 | NETD、MRTD、ΔT 偏差、对比度秩相关 | NETD/MRTD 是热像仪通用口径；任务级用 TTP 度量（NVESD 2004 报告） |
| 雷达 | RCS 误差（dB）、Pd/Pfa 与理论曲线的一致性、SNR | 检测性能的闭式关系用 Albersheim 近似（Proc. IEEE 1981）核对，避免门限拍脑袋 |
| SAR | 冲激响应宽度 IRW、峰值旁瓣比 PSLR、积分旁瓣比 ISLR、等效噪声后向散射系数 NESZ | 自 SARAS（IEEE TGRS 1992）以来 SAR 原始信号/图像仿真的通用验收项 |
| LiDAR | 测距偏差、点密度、强度一致性 | 与 DIRSIG LIDAR 手册的 truth 口径一致（距离、入射角余弦） |
| 跨模态 | 3D 框投影一致率、帧号对齐误差、遮挡/截断标注一致性 | DIRSIG truth 的 distance / viewcosine / 法线分量 / hit fraction 提供了逐像素可核对的量 |

### 3.5 由此得到"必须报告字段"的三条硬规则

1. **凡是"默认值"都必须写出来，并标注它是库默认还是实测标定。** 依据 §3.1 的"最优 vs 通用参数"结论：不写就等于让读者默认你用了一切最优。
2. **凡是"派生量"都必须写公式或给数值。** 例如距离分辨率由带宽推 c/2B、目标像素跨度由 IFOV 与距离推。DIRSIG 把 data units 强制写进图像头，就是这条规则的极端形式。
3. **凡是"随机性"都必须给种子与采样数。** 采样数决定蒙特卡洛噪声（DIRSIG 20/100 路径的默认值讨论），种子决定可复现（radarsimpy 的 seed）。缺这两个，数据集连自己都复现不了。

## 4. 落地：六个收纳箱

### 4.1 分箱的三条硬规则

1. **按"谁产生这个量"归属**（Rendered.ai 端口语义）。目标像素跨度虽然影响视场，但它由"目标尺寸 + 距离 + IFOV"派生，跨在轨迹与传感器之间，因此放在 A 箱只作为**只读回显**，可编辑项在 C 与 D。
2. **按"物理量所在层"归属**（DIRSIG 的入瞳→焦平面→DN 三段）。凡是改变入瞳辐亮度的（场景、材质、天气、太阳）进一箱；凡是改变焦平面辐照度与电子数的（孔径、焦距、像元、积分时间、增益）进另一箱。
3. **一箱首屏 ≤ 9 个可见控件，其余进高级**，且每个高级项必须带"默认值 + 什么时候该改 + 改了会坏在哪"三段提示（照抄 radarsimpy gate_delay 的写法）。

### 4.2 六箱与现有 34 个控件的归属

| 箱 | 现有控件（studio 里的 id） | 处理 |
|---|---|---|
| A 场景与目标 | scene、size(小/中/大)、pxLo、pxHi | pxLo/pxHi 改为只读回显（由 C 的 IFOV 与 D 的距离区间派生）；size 三档保留为"目标尺度语义" |
| B 环境与大气 | weather | 扩成 8 维状态向量（云量、能见度、雨强、风速、气温、湿度、太阳高度角、海况），weather 变成"预设按钮"而非唯一入口 |
| C 传感器组 | sensors、viewsMode、nFov/nW/nH、wFov/wW/wH、sarOn、sarBand、sarBw、sarPol、sarSquint | 每个模态一张"传感器卡片"；viewsMode 降级为"卡片数量"，不再是模式开关 |

### 4.4 交互约定（三条，直接决定实现）

1. **参数口分"字面值"与"链接值"**：像 Rendered.ai 的输入口一样，每个字段允许 {value: …} 或 {link: "B.weather.rain_rate"}。这样"雷达雨衰跟着天气走"这条耦合变成配置而不是硬编码，且能自动画出依赖图用于失效传播。
2. **派生量只读且显示公式**：带宽 100 MHz → 距离分辨率 1.50 m（c/2B）；FOV 2.2° @960 px → IFOV 2.29 mrad → 1500 m 处像素跨度。现在 sarRes 已经是只读回显，做法正确，应推广到 pxLo/pxHi。
3. **两档精度共享同一份参数**：E 箱的"精度档"只改采样类参数（路径数、弹射次数、积累脉冲数），不改场景/传感器/轨迹。SE-WORKBENCH 的两个计算核证明这条可行，且能避免"预览和交付是两套配置"这种最常见的工程债。

### 4.5 分箱的验收标准（可测）

- 首屏可见控件数 ≤ 9/箱，展开全部高级项后 ≤ 20/箱；
- 从"想改雨强"到"点了生成"的点击深度 ≤ 3（B 箱 → 预设 → 生成）；
- 任意参数变更后，受影响的箱在 200 ms 内标红（依赖图由 §4.4 的链接关系自动生成）；
- 同一份配置分别以"预览/交付"两档跑出的产物，其 数据集说明.md 除采样字段外**逐字节一致**。

| E 求解与质量 | dataset.py 中的采样常量、_render_cfg | 采样类常量从代码里提到配置层，并声明"预览/交付"两档；种子贯穿全部子模块 |
| F 产物与标注 | dataset.py、labels.py | 标注只由 3D 框投影产生；数据集说明由 F 箱在生成结束时**直接写出**（字段来源见 §4.7），不做事后补写 |

### 4.7 schema 是单一真源

一份参数 schema（六个顶层键 scene / environment / sensors / platform / solver / output，每个字段带 type、unit、default、risk、advanced 标记）同时生成三样东西：**界面控件**（含分箱与折叠）、**运行时校验**（量纲与取值范围）、**数据集说明的字段表**（表 2 的"传感器/环境/质量/复现"四组几乎可以逐字段映射）。

这是 Rendered.ai 的 schema 驱动（一个 node 一份 yml，同时定义 GUI 与执行）与 DIRSIG 的"参数表即手册"两件事的合流：**只要 schema 写全，界面不必手写、文档不必手写、校验不必手写**。反过来，任何在界面上手加的控件都会立刻变成文档缺口——这也是为什么 §4.1 的第一条规则（按谁产生归属）必须严格，否则 schema 会长出重复字段，而重复字段一定会漂移（§4.2 的 sarAlt/pAlt 就是现成反例）。

| # | 箱 | 物理边界（管什么） | 基础项（默认展开） | 高级项（默认收起） | 关键约束 |
|---|---|---|---|---|---|
| A | 场景与目标 | 决定"入射到入瞳之前"的几何与物性：谁在那里、什么材质 | 场景模板、目标资产、材质预设（3 格：发射率/albedo/粗糙度）、目标尺度档、目标像素跨度（只读）、背景类型（空/地/海） | 材质发射率曲线（91 点）、多层与复合材料、下垫层、UV 与贴图、几何简化容差、plume/尾焰 | 材质只描述物质不描述温度；缺省项由另两项推导（DIRSIG 规则） |

| D | 平台与轨迹 | 6DOF 时间序列：谁在动、怎么动、看哪里 | 轨迹模式、接近方式、接近速率、视线距离区间、平台高度、平台速度、航向 | 俯冲角、蛇形振幅/频率、起点后撤、结束距离、视线角速率、抖动谱、逐帧外参导出 | 平台高度/速度是唯一真源，SAR 卡不得再存一份；距离区间与 IFOV 共同决定像素跨度 |
| E | 求解与质量 | 数值求解器的档位与收敛控制：不改变物理，只改变误差 | 精度档（预览/交付）、每像素路径数（20–100）、最大弹射次数、随机种子、收敛阈值 | 相干积累脉冲数、SAR 方位向过采样、重要性采样开关、MIS 补偿、真值收集项勾选 | 两档共享同一份 A–D 参数；种子必须进产物元数据 |
| F | 产物与标注 | 落到磁盘的东西：文件名、数量、格式、标注、说明文档 | 数据集名、段数×每段帧数、帧率、模态勾选、split 策略、干扰增广、最小目标像素、COCO 导出、数据集说明自动生成 | 帧命名规则、压缩与位深、KITTI 附加导出、负样本比例、类别合并表、真值栅格导出、清单哈希 | 标注由 3D 框统一投影，禁止各模态独立标；色标范围属本箱不属 C 箱 |
