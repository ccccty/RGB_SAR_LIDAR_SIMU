# 多模态目标数据集流水线：需求拆解、开源检索与建设方案 v1

> 目标（用户原话拆解）
> 1. 输入目标图片或 3D 模型 → 软件进一步细化
> 2. 同一目标在不同天气（晴/多云/雨）与不同场景（空/地/海）下的真实视频或图像切片、轨迹
> 3. 模态：光学、红外、指定波段雷达
> 4. 输出一套 COCO 数据集

---

## 0. 先说结论

**能做，而且不需要从零开始**：需要把「一条流水线」拆成 6 个可独立验证的模块，
其中 3 个半我们已经有可用实现（simkit），剩下 2 个半是本期要建的。

真正的难点不是"渲染得像"，而是三件事：
1. **跨模态物理一致**：光学里"阴天"、红外里"云层遮挡天空辐射"、雷达里"雨衰"，必须是同一个
   物理状态机的三个输出，不能三套各拍各的；
2. **sim2real 偏差可量化**：每加一个天气/场景，都要有"和实拍差多少"的指标，否则数据集越做越像自娱自乐；
3. **标注一致性**：光学/红外/雷达三模态的框必须是同一个 3D 框投影出来的，帧号严格对齐。

## 1. 开源生态检索结果（2026-10 现状）

### 1.1 雷达
| 项目 | 许可 | 能借什么 | 能否进交付物 |
|---|---|---|---|
| radarsimx/radarsimpy ★589 | **GPL-3.0** | 射线追踪 RCS、FMCW/MIMO 波形、SAR/ISAR 成像流程 | **不能**闭源集成（GPL 传染）。只可参考算法，自己实现 |
| chstetco/virtualradar ★131 | MIT | 毫米波雷达仿真框架，可借鉴场景/信号组织方式 | 可以 |
| ekurtgl/FMCW-MIMO-Radar-Simulation ★365 | 无 | 教材式 FMCW/MIMO 推导与代码 | 参考 |
| blirs/BLIRS ★16 | 不明（NOASSERTION） | 2017 年斯图加特大学「Blender + MATLAB 做雷达仿真」 | 仅参考。绑死 Blender 2.77，已过时 |
| gprMax ★895 | GPL-3.0 | FDTD 全波电磁（近场、埋地目标） | 不能闭源集成 |

结论：**雷达这一路我们已经自己实现了 PO 面元 RCS + FMCW 拍频 + 距离-多普勒**，
不引入 GPL 依赖是正确选择；要补的是**频段预设、雨衰、海杂波、极化**。

### 1.2 红外
| 项目 | 许可 | 能借什么 | 备注 |
|---|---|---|---|
| slcs-jsc/jurassic ★16 | GPL-3.0 | DLR 快速红外辐射传输（大气廓线 → 透过率/辐亮度） | 只能当"对照真值"，不能链接进交付物 |
| jpaguerre/ThRend ★44 | 无 | LWIR 热成像渲染思路（Blender 侧） | 可读源码借鉴 |
| blirs/BLIRS | 不明 | Blender 材质热属性工具箱 | 过时 |

结论：**没有可直接复用的工业级开源红外场景仿真器**（DIRSIG / MuSES / SE-WORKBENCH 都是闭源商业件）。
我们在 simkit 里的"逐面元稳态热平衡 + Planck 谱段积分 + 探测器效应"已经是同量级的开源替代。

### 1.3 天气 / 大气 / 海面
没有现成的"天气数据集生成器"，但物理模型是公开且成熟的（见第 3 节公式表）。
渲染侧可借：Mitsuba 3（光谱渲染 + 参与介质，Apache-2.0）、Blender 体积散射、LibRadtran（大气，GPL）。

### 1.4 图像 → 3D（需求 1 的前半句）
| 项目 | 许可 | 说明 |
|---|---|---|
| Tencent-Hunyuan/Hunyuan3D-2 ★15k | NOASSERTION（腾讯自有，需读条款） | 单图 → 带纹理 mesh，当前最强开源档 |
| stabilityai/TripoSR | MIT | 单图快速出 mesh（质量中等，速度快） |
| microsoft/TRELLIS | MIT | 单图/文生 3D，结构完整性好 |
| TencentARC/InstantMesh | Apache-2.0 | 多视图扩散 + LRM |
| COLMAP + OpenMVS + mvs-texturing | BSD | **摄影测量**：多张实拍 → 高保真 mesh + 贴图（最可信） |

**重要判断**：图像生成 3D 会给目标识别训练引入**系统性几何偏差**（生成模型会"补"出实车没有的结构）。
涉密/装备类目标建议：**CAD/摄影测量为主，生成模型只用于背景/干扰物/数据增广**。

## 2. 能力矩阵（需求 → 现状）

| 需求 | 模块 | 现在 | 缺口 |
|---|---|---|---|
| 1 输入 3D 模型并细化 | assets | OBJ 导入、按高度归一化、材质分区（11 种）、box/cylinder 基元 | 缺 FBX/STEP 转换、UV/贴图、凸包简化、多材质分区标注 |
| 1 输入图片转 3D | assets.image2mesh | 无 | 外挂本地模型（Hunyuan3D/TripoSR）或 COLMAP 流水线 |
| 2 天气 | weather | 只有 air.temp/rh/wind + 太阳 + 大气 tau 常数 | **缺天气状态机**：云量→辐照/天空温度、雨强→雨衰/雨杂波/路面积水、能见度→雾的散射 |
| 2 场景（空/地/海） | env | 只有平地"地" | 缺**海面**（Cox-Munk 斜率 + 波浪几何 + 海杂波）、缺**空中**背景（云层/地平线/天空梯度） |
| 2 视频/轨迹 | platform | 已有 turntable 环拍 + 直线速度 | 缺 6DOF 轨迹文件（平台+目标）、视线角变化、逐帧外参导出 |
| 3 光学 | optical | Blender/Cycles 后端已通，含太阳/天空/阴影 | 缺雨雾体积散射、湿地面反射、云层贴图 |
| 3 红外 | ir | 逐面元热平衡 + Planck 8–12 µm + NETD/PSF + 固定 200–450 K 编码 | 缺**多波段**（3–5 µm 中波、1–3 µm 短波）、缺雨雾对红外的衰减、缺云层遮蔽 |
| 3 雷达 | radar | 77 GHz FMCW、PO 面元 RCS、距离-多普勒、3D 框 + 点云 | 缺**频段预设**（X/Ku/Ka/W）、极化、雨衰、海杂波、多径 |
| 4 COCO | labels | 红外+光学 COCO、雷达 3D JSON、split/stats | 缺分割掩码、缺 COCO 之外的 KITTI（可选） |

## 3. 经验公式清单（可直接实现的物理模型）

### 3.1 大气与天气（三模态共用同一个"天气状态"）
| 量 | 公式 | 参数/取值 |
|---|---|---|
| 雾/霾能见度 ⇄ 消光 | 科希米德 Koschmieder：V = 3.912 / β，T = exp(−β·d) | V：能见度 m；β：消光系数 1/m。轻雾 V=2000 m，浓雾 V=200 m，霾 V=5000 m |
| 雨强 → 雨滴谱 | Marshall–Palmer：Z = 200·R^1.6（Z 单位 mm⁶/m³，R 单位 mm/h） | 小雨 1、中雨 4、大雨 16、暴雨 64 mm/h |
| 雨衰（雷达） | ITU-R P.838：γ_R = k·R^α (dB/km)，k、α 随频率与极化变化 | X 波段 ≈ 0.01·R^1.28；Ku ≈ 0.04·R^1.19；Ka ≈ 0.2·R^1.07；W 波段更强 |
| 气体吸收（雷达） | ITU-R P.676 逐线积分（O₂ 60 GHz 吸收峰、H₂O 22/183 GHz） | 74/77 GHz 有 O₂ 吸收线，必须查表 |
| 云层遮蔽（红外/光学） | 云底高度 + 云量 → 视在天空温度与太阳直射比例 | 云量 0–1；低云 300 m、中云 3000 m、高云 8000 m |
| 天空长波温度 | Swinbank：T_sky = 0.0552·T_air^1.5（K）；云天下向云底温度收敛 | 晴天 T_air=300 K → T_sky≈287 K；阴天 ≈ T_air |
| 天空散射（光学） | 晴空 Preetham/Hosek/Nishita；阴天改为均匀漫射穹顶 | 直接对应 Blender 的 Sky 模型 |
| 雨/雾对红外衰减 | 消光系数按雨强/含水量线性插值（Mie 近似） | 待用实测数据标定 |

> 关键设计：**天气是一个 8 维状态向量**（云量、能见度、雨强、风速、气温、湿度、太阳高度角、海况），
> 三个传感器都从它派生，保证"同一时刻三模态说的是一件事"。

### 3.2 海面
| 量 | 公式 | 说明 |
|---|---|---|
| 海面斜率分布 | Cox–Munk：均方斜率 σ² = 0.003 + 5.12e−3 · U（U 为 10 m 风速 m/s） | U=5 → σ≈0.026；U=10 → σ≈0.051 |
| 海浪谱 | Elfouhaily / Pierson–Moskowitz：S(k) ∝ k⁻³ … | 生成波浪几何用 |
| 二尺度散射 | 大尺度面元做镜面（PO），小尺度做 Bragg 微扰 | 与现有面元 PO 模型拼接 |
| 海杂波（掠射角小） | Nathanson/GIT 模型：σ₀ 随擦地角、海况、频率、极化变化 | 需要标定表（X/Ku/Ka 各自一条曲线） |
| 白浪覆盖率 | W = 3.84e−6 · U^3.41 | 影响光学亮斑与红外温度 |

### 3.3 红外热平衡（已有，补两项）
| 项 | 现状 |
|---|---|
| 太阳短波吸收 α·G·cosθ | 已有 |
| 天空/地面长波（视因子） | 已有 |
| 对流换热 h = 5.7 + 3.8·v | 已有 |
| 内热源（发动机/电子设备） | 已有（internal_heat） |
| **潜热/蒸发（湿地面、海面）** | 待加：湿表面蒸发降温，海面按水汽压算 |
| **云层对净辐射的影响** | 待加：云量 → 下向长波升高、太阳直射降低 |

### 3.4 雷达（已有 + 待补）
已有：PO 面元 σ = 4πA²cos²θ/λ²·ρ²·coh、Kirchhoff 粗糙度、雷达方程、热噪声、相干积累、拍频合成。
待补：频段预设、雨衰、海杂波、极化（HH/VV/HV）、多径（海面/地面镜像）。

## 4. 需要你提供的输入（按优先级）

### 必须
1. **目标 3D 模型**：OBJ/FBX/STEP 任一；带真实尺寸（长宽高）与朝向定义（哪个轴是前向）
2. **材质分区**：哪些面是金属/涂装/玻璃/橡胶/蒙皮（贴图或分组即可），这直接决定红外温度与雷达 RCS
3. **雷达参数**：频率（X 9.5 / Ku 15 / Ka 35 / W 77 或 94 GHz）、带宽、极化、天线增益与波束宽度、作用距离
4. **光学/红外参数**：焦距/FOV/分辨率、红外波段（3–5 或 8–12 µm）、NETD、像元尺寸
5. **COCO 类别定义**：类别名、是否要分割掩码、最小目标像素尺寸

### 强烈建议（决定 sim2real 能不能收敛）
6. **少量实拍基准**：同一目标在晴/阴/雨各 ≥20 张（光学 + 红外更佳），用来标定与验收
7. **场景清单**：空/地/海的典型背景、季节、时刻（上午/正午/黄昏/夜）、云量、能见度、海况
8. **平台轨迹**：接近/绕飞/俯冲等运动模式，或直接给航路点表格

### 有则更好
9. 实测 RCS 或雷达点云（用来定 rcs_db 与杂波电平）
10. 目标红外热像（用来定 α/ε 与内热功率）
11. 算力清单：GPU 型号与数量、是否可离线部署 PyTorch/CUDA

## 5. 建设路线（按周排，每阶段有验收指标）

### P0（1 周）天气状态机 + 三场景背景
- 实现 weather 模块：8 维状态向量 → 太阳/天空/大气/地面湿度的派生量
- 场景模板：空地、城市道路、海面（平静/中浪/大浪）
- 验收：同一场景切换 晴→阴→雨，三个模态**同时**变化且物理自洽（例：阴天红外天空温度升高、光学照度下降、雷达雨衰增加）

### P1（2–3 周）海面 + 雷达频段 + 雨雾
- Cox-Munk 海面几何 + 二尺度散射 + 海杂波表
- 频段预设 X/Ku/Ka/W（含各自衰减与波束参数）
- 光学：雨丝、雾（体积散射）、湿地面镜面反射
- 验收：雷达在四个频段对同一目标 RCS 随 λ 的变化符合 PO 预期；雨强 0/4/16 mm/h 下信噪比下降量可解释

### P2（2–3 周）轨迹与视频
- 6DOF 轨迹文件（平台位置+姿态、目标位置+姿态、时间戳）
- 逐帧相机外参导出；motion blur（可选）
- 验收：连续 300 帧视频序列，标注与帧严格对齐，无跳变

### P3（2 周）图像→3D 外挂 + 材质反演
- 本地部署 TripoSR/Hunyuan3D（离线权重），输出 OBJ → 自动归一化 → 进入现有流水线
- 材质反演：从实拍图估计 albedo/粗糙度，映射到材质库
- 验收：生成的模型在红外下温度分布合理，且在光学里与原图轮廓 IoU > 0.8

### P4（持续）sim2real 校验
- 指标：光学 SSIM/色彩分布 KL、红外 ΔT 误差（±2 K）、雷达 RCS 误差（±3 dB）
- **终极指标**：仿真数据训练 → 实拍测试集上的 mAP（这才是唯一硬指标）

## 6. 关于"用 REA 逆向开源软件"

澄清一个方法论问题：

| 对象 | 正确做法 | 为什么 |
|---|---|---|
| 开源项目（radarsimpy/BLIRS/ThRend…） | **直接读源码**，必要时 clone 下来读 | 源码是最完整的"真相"，逆向二进制是舍近求远 |
| 闭源商业件（DIRSIG / MuSES / SE-WORKBENCH / SensorVision） | REA（Ghidra）静态分析 | 只能拿到导出符号、字符串、数据表；**能拿到参数语义，拿不到可用管线** |
| 授权校验（FlexLM/加密狗） | **不做** | 违法且对生成数据无收益 |

REA 在本项目里真正有用的场景只有一个：**如果你们手上有 DIRSIG 或 SensorVision 的正版安装**，
用它把材质热物性表、大气查表、传感器参数命名体系扒出来，直接校准我们的物理模型。
这比"逆向出一个渲染器"现实一百倍。

## 7. 一句话

这套东西本质上是「**一个物理状态机 + 三个前向模型 + 一条标注链**」。
我们已经有了红外和雷达的前向模型与标注链，缺的是天气状态机、海面、频段预设和轨迹系统——
这四块都是**公式已知、工程量明确**的活，不是研究风险。
